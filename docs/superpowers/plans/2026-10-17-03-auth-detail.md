> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**เป้าหมาย:** ผู้ใช้ล็อกอินด้วยอีเมล OTP (หรือกดปุ่มสลับผู้ใช้เดโม) แล้วเปิดแผงรายละเอียดของเรื่อง กด "เจอเหมือนกัน" และแสดงความคิดเห็นได้ โดยลำแสงบนแผนที่ของทุกคนที่เปิดอยู่อัปเดตทันทีผ่าน Realtime Broadcast

**ไม่อยู่ในแผนนี้:** ปุ่ม "แจ้งว่าแก้แล้ว" และเมนูรายงานเนื้อหา (แผน 5 ทำพร้อม endpoint), rate limit และกรองคำหยาบของความคิดเห็น (แผน 4 ทำรวมกับการแจ้งเรื่อง), หน้า `/me` และการตั้งชื่อที่แสดง (แผน 4), สองภาษา (แผน 6 ข้อความในแผนนี้เป็นภาษาไทยในโค้ดเหมือนแผน 2), และการจัดวาง UI ใหม่ทั้งหน้า (แผน 8)

**สถาปัตยกรรม:**
- **ตรวจ JWT แบบ JWKS (ES256) ไม่ใช้ HS256** เพราะตรวจเครื่องจริงแล้ว (2026-10-17, Supabase CLI 2.121.0) access token ของผู้ใช้มี header `{"alg":"ES256","kid":"b81269f1-…"}` และ `/auth/v1/.well-known/jwks.json` มีคีย์ EC P-256 ส่วน `JWT_SECRET` (HS256) ใช้เซ็นได้แค่ anon key กับ service key แบบเก่า ถ้าตรวจด้วย HS256 token ของผู้ใช้จะไม่ผ่านเลยสักอัน ข้อดีอีกอย่างคือ API ใช้แค่กุญแจสาธารณะ ไม่ต้องถือ secret และ `createRemoteJWKSet` ของ `jose` โหลดคีย์ใหม่เองเมื่อเจอ `kid` ที่ไม่รู้จัก (เช่นหลัง `supabase stop/start`) สเปกหัวข้อ 4.1 จะแก้ตามใน Task 11
- **API:** ทุก route ที่เขียนข้อมูลผ่าน `requireMember` ซึ่งตรวจ token แล้วอ่าน `profiles` ด้วย service role ถ้าไม่มี token หรือ token ใช้ไม่ได้ตอบ 401 ถ้า `banned_at` ไม่ว่างตอบ 403 ส่วนตรรกะที่ต้อง atomic (สลับเจอเหมือนกัน, เพิ่มความคิดเห็น) อยู่ในฟังก์ชัน SQL ที่ให้ใช้ได้แค่ `service_role` จึงทดสอบด้วย pgTAP ได้ และ API เป็นแค่ชั้นบางๆ ที่ทดสอบด้วย fake store
- **Realtime:** หลังเขียนสำเร็จ API ส่ง `{id, status, confirm_count, comment_count}` ไปที่ channel สาธารณะ `reports` event `report` ผ่าน REST `POST /realtime/v1/api/broadcast` แบบไม่รอผล ถ้าส่งไม่ได้ก็แค่ log การเขียนยังสำเร็จ
- **เว็บ:** หน้าแผนที่ใช้ route เดียวสำหรับ `/` และ `/r/:id` (`UrlMatcher`) และใช้ `AppRouteStrategy` ที่บังคับให้ reuse component นี้ เพราะ `IonicRouteStrategy` จะสร้างหน้าใหม่เมื่อ params เปลี่ยน ซึ่งทำให้มีแผนที่และ WebGL context สองชุด การล็อกอินจากในแผนที่เปิดเป็น modal (ไม่ออกจากหน้า) ส่วน `/login` เป็นหน้าสำหรับลิงก์ตรงและแผนถัดไป ซึ่งกลับด้วย `navigateRoot` ที่ล้าง stack ของ Ionic เสมอ
- **แผงรายละเอียด:** component เดียว วางในแผงขวา 380 px ที่จอ ≥ 820 px และอยู่ใน `ion-modal` แบบ sheet (`breakpoints [0, 0.64, 1]`) บนจอแคบ

## จุดที่ต้องตรวจเป็นพิเศษ

1. **token หมดอายุระหว่างใช้งาน** (`jwt_expiry = 3600`): ถ้าเปิดแผงค้างไว้เกินชั่วโมงแล้วกดเจอเหมือนกัน ต้องได้ผลปกติ `ApiService` ต้องขอ session ล่าสุดทุกครั้ง และเมื่อได้ 401 ให้ refresh 1 ครั้งแล้วลองใหม่ (เทสต์ใน Task 6)
2. **กดเจอเหมือนกันรัวๆ:** ระหว่างรอคำตอบ ปุ่มต้อง disabled และตัวเลขต้องตรงกับที่ server ตอบล่าสุด (เทสต์ใน Task 9) ฝั่ง DB ล็อกแถว `reports` ก่อนสลับ (Task 2)
3. **ลิงก์ `/r/:id` ที่เปิดไม่ได้:** id ที่ไม่ใช่ uuid, เรื่องที่ยัง `pending_review`/`rejected`/`hidden` หรือไม่มีอยู่จริง ต้องขึ้น toast "ไม่พบเรื่องนี้…" แล้วกลับไปที่ `/` โดยไม่ crash และ API ต้องตอบ 404 `report_not_found` ไม่ใช่ 500 (เทสต์ใน Task 4 และ 9)
4. **`next` ของหน้า `/login` พาออกนอกเว็บ:** `next=//evil.example`, `next=https://evil.example` หรือ `next=/\evil` ต้องกลับไปที่ `/` (เทสต์ใน Task 7)
5. **ความคิดเห็นที่มีแต่ช่องว่าง หรือยาว 501 ตัวอักษร:** API ตอบ 400 `invalid_body` และปุ่มส่งฝั่งเว็บ disabled ตั้งแต่แรก (เทสต์ใน Task 4 และ 9)
