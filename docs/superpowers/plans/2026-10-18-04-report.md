**สถาปัตยกรรม:**
- **ฐานข้อมูลเป็นเจ้าของกฎที่ต้อง atomic** ฟังก์ชัน SQL ที่ให้ใช้ได้แค่ `service_role` (เหมือน `toggle_confirmation` ของแผน 3) ได้แก่ `register_photo`, `create_report`, `find_duplicates`, `merge_duplicate`, `delete_orphan_photos` และ `add_comment` ฉบับใหม่ ทุกตัวที่นับโควตาล็อกแถว `profiles` ของผู้ใช้ก่อนนับ (`select … for update`) เพื่อให้คำขอพร้อมกันไม่ทะลุ rate limit ส่วน API เป็นชั้นบางที่ตรวจ token, ตรวจรูปแบบ, กรองคำหยาบ, ประมวลผลรูป แล้วเรียกฟังก์ชันเหล่านี้
- **รูปผ่านสองรอบ:** เบราว์เซอร์อ่าน GPS จาก EXIF (`exifr`) แล้วย่อเป็น WebP/JPEG ด้วย canvas จากนั้น API ตรวจ magic bytes → `sharp` encode ซ้ำ (หมุนตาม EXIF orientation ก่อนลบ metadata, ด้านยาว ≤ 1600 px) → `processForPrivacy` (คืนรูปเดิม `blurred=false` จนกว่าแผน 9 จะมาแทน) → thumbnail 400 px → เก็บใน `photos-private` ที่ `{uploader_id}/{photo_id}.webp` และ `…_thumb.webp` (ตอนอัปโหลดยังไม่มี `report_id` แผน 5 ย้ายเป็น `{report_id}/{photo_id}.webp` ตอนอนุมัติ)
- **อัปโหลดรูปทันทีที่เลือก** (ขั้น 1) ไม่รอกดส่ง ตอนส่งจึงส่งแค่ `photo_ids` รูปที่ไม่ถูกผูกกับเรื่องภายใน 24 ชั่วโมงถูกกวาดทิ้งโดย `delete_orphan_photos` (งานค้างจากแผน 1) ซึ่ง API เรียกตอนสตาร์ตและทุกชั่วโมง

- **เว็บ:** ร่างเรื่องอยู่ใน `ReportDraftService` (signal, ระดับ root) เพื่อให้ย้อนกลับไปมาระหว่าง 3 ขั้นไม่เสียรูป ส่วนขั้น 3 ใช้ `MAP_FACTORY` ตัวเดิม (positron เปล่า ไม่มีทะเล shader) เพื่อไม่ให้มี WebGL context หนักสองชุด

## การตัดสินใจที่ผู้เขียนแผนเลือกเอง (เจ้าของค้านได้ก่อนลงมือ)

สเปกเงียบหรือกำกวมในจุดต่อไปนี้ แผนเลือกไว้แบบนี้:

1. **กันซ้ำเทียบกับ `public_location` ไม่ใช่พิกัดจริง** ถ้าเทียบกับพิกัดจริง ผู้ใช้ยิง `check-duplicate` หลายจุดแล้วรู้ว่าเรื่อง hazard อยู่ตรงไหนได้ (trilateration) ซึ่งทำลายการเลื่อน 150 ม. ราคาที่จ่ายคือเรื่อง hazard ที่ถูกเลื่อนอาจไม่ถูกจับว่าซ้ำ คำตอบไม่ส่งระยะทางหรือพิกัดกลับ
2. **"ต่อวัน" = ย้อนหลัง 24 ชั่วโมง** (rolling) ไม่ใช่วันตามปฏิทิน เพราะนับจาก `created_at` ได้ตรงๆ ไม่ต้องตัดสินเรื่องเขตเวลา
3. **เพิ่มโควตารูป** `RATE_LIMIT_PHOTOS_PER_DAY` (ค่าเริ่มต้น 40) เพราะอัปโหลดรูปก่อนมีเรื่อง ถ้าไม่จำกัดจะอัปโหลดรูปกำพร้าได้ไม่อั้น (สเปก 6.2 ไม่มีข้อนี้)
4. **endpoint ที่เพิ่มจากตารางในสเปก 6:** `GET /me/reports` (รูปของเรื่องที่ยังไม่อนุมัติอยู่ใน bucket ส่วนตัว ต้องเซ็น URL ด้วย service role), `PATCH /me` (ชื่อที่แสดงปรากฏสาธารณะในความคิดเห็น จึงต้องผ่านตัวกรองคำหยาบ — ดังนั้น migration นี้ **ถอนสิทธิ์ที่ client แก้ `profiles.display_name` ตรงๆ** เหลือแค่ `locale`) และ `POST /reports/:id/merge` ("ใช่ กดเจอเหมือนกันแทน" ต้องนับ +1 แบบไม่สลับ ถ้าใช้ `/confirm` ซึ่งเป็น toggle คนที่เคยกดไว้แล้วจะถูกยกเลิก) แก้ตารางในสเปกตอนปิดงาน
5. **รูปในการ์ดเรื่องซ้ำ:** ใช้รูปแรกเป็นรูปแนบในความคิดเห็น (`comments.photo_id` เก็บได้รูปเดียว) รูปที่เหลือไม่ถูกผูก จึงถูกกวาดทิ้งตามเวลาปกติ รูปของความคิดเห็นถูกย้ายไป `photos-public` ทันที เพราะเรื่องนั้นสาธารณะอยู่แล้ว
6. **ตัวกรองคำหยาบ** จับคำไทยด้วย `Intl.Segmenter('th')` แล้วเทียบเป็นคำเต็ม ไม่ใช้ substring เพราะภาษาไทยไม่มีช่องว่าง ("ค้นหา" จะโดนคำที่มี "หา" ถ้าตัดวรรณยุกต์แล้วเทียบ substring) ส่วนอังกฤษเทียบแบบ word boundary หลังแปลง leetspeak ง่ายๆ
7. **ตำแหน่งปุ่มลอย "แจ้ง"** บนมือถือชนกับคอลัมน์ปุ่มควบคุมมุมล่างขวาของ `DESIGN.md` ให้ขั้น `/impeccable shape` เป็นคนวางตำแหน่ง (ข้อบังคับ: ไม่ทับปุ่มควบคุม/attribution, ≥ 44 px, นิ้วโป้งเอื้อมถึง, ซ่อนเมื่อแผงรายละเอียดเปิดบนมือถือ)

## จุดที่ต้องตรวจเป็นพิเศษ

1. **กดส่งซ้ำ/โควตาพร้อมกัน:** `POST /reports` ซ้ำด้วย `photo_ids` ชุดเดิมต้องไม่สร้างเรื่องที่สอง (รูปถูกผูกไปแล้ว → 400 `invalid_photos`) และยิง 6 คำขอพร้อมกันตอนโควตา 5 ต้องได้ 201 ห้าและ 429 หนึ่ง ไม่ใช่หก (เทสต์ใน Task 3, 9 และ 11)
2. **พิกัด hazard รั่ว:** `place_name`, หัวข้อเริ่มต้น และผลกันซ้ำของเรื่อง hazard ต้องคำนวณจากพิกัดที่เลื่อนแล้ว ไม่ใช่พิกัดจริง และ `/me/reports` ต้องไม่ส่งพิกัดจริงออกไป (เทสต์ใน Task 2, 3, 7)
3. **รูปที่ไม่ใช่รูป / รูปของคนอื่น:** ไฟล์ข้อความที่ตั้งชื่อ `.jpg`, รูป PNG ที่ใหญ่เกิน 40 ล้านพิกเซล (decompression bomb), รูปมือถือที่หมุนด้วย EXIF orientation, `photo_ids` ของผู้ใช้อื่น, id ที่ไม่มีจริง และ 0 หรือ 5 รูป ต้องถูกปฏิเสธหรือจัดการถูกต้องโดยไม่ 500 (เทสต์ใน Task 3, 4, 6)
4. **ไม่มีพิกัดจากที่ไหนเลย** (รูปไม่มี EXIF และผู้ใช้ไม่ให้สิทธิ์ GPS): หมุดต้องไม่ตกที่ (0,0) หรือกลางประเทศแล้วส่งได้ทันที ให้เริ่มที่ภาพรวมประเทศและบังคับซูมถึง 14 ก่อนส่งได้ (เทสต์ใน Task 11)
5. **ค้นหาด้วยอักขระพิเศษ:** `q` เป็น `%`, `_`, `\`, `#` หรือ `#%` ต้องค้นหาตัวอักษรนั้นตรงๆ ไม่ใช่ wildcard (เทสต์ใน Task 2 และ 9)
