# แจ้ง — Plan 5: แอดมินและวงจรชีวิตของเรื่อง

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**เป้าหมาย:** แอดมินเปิด `/admin` แล้วอนุมัติ (แก้หมวด ระดับ หัวข้อ และตำแหน่งที่แสดงได้) หรือปฏิเสธเรื่องใหม่พร้อมเหตุผล, ยืนยันหรือปฏิเสธ "แจ้งว่าแก้แล้ว", จัดการเนื้อหาที่ถูกรายงาน (ยกเลิก / ซ่อน / แบน), ค้นหาและแบนผู้ใช้ และดูบันทึกทุกการกระทำ ส่วนสมาชิกกด "แจ้งว่าแก้แล้ว" (แนบรูปหลังแก้และหมายเหตุได้) และรายงานเรื่องหรือความคิดเห็นจากแผงรายละเอียดได้ เมื่อจบแผนนี้สถานการณ์เดโมข้อ 1–5 ในสเปกหัวข้อ 1.1 ทำได้ครบ

**ไม่อยู่ในแผนนี้:** สองภาษา, โหมดมืด, `/list`, `/about`, ตัวเลขกำลังใจ (แผน 6 — ข้อความในแผนนี้เป็นไทยในโค้ดเหมือนแผน 4), ปุ่ม back ของ Android และ GPS/กล้อง native (แผน 7), การจัดวาง UI ใหม่ทั้งแอปและ E2E (แผน 8), การเบลอรูปและป้าย "เบลอแล้ว" ในหน้าแอดมิน (แผน 9), การลบหรือรวมแท็ก (สเปก 3.7 บอกว่าแอดมินทำได้ แต่ไม่อยู่ในหัวข้อ 3.10 และไม่ใช่ฉากเดโม — ยกไปแผน 8)

**สถาปัตยกรรม:**
- **ฐานข้อมูลเป็นเจ้าของ state machine** ทุกการเปลี่ยนสถานะ (อนุมัติ, ปฏิเสธ, แจ้งแก้, ยืนยันแก้, ซ่อน, คืน, ซ่อนอัตโนมัติ, แบน) เป็นฟังก์ชัน SQL `security definer` ที่ให้ใช้ได้แค่ `service_role` เหมือนแผน 3–4 แต่ละตัวล็อกแถวเป้าหมาย (`for update`) แล้วตรวจสถานะก่อนเปลี่ยน คำขอซ้อนกันจึงสำเร็จได้ครั้งเดียว ที่เหลือได้ `invalid_state` และทุกตัวเขียน `moderation_log` ในธุรกรรมเดียวกัน
- **ผลข้างเคียงรูปแบบเดียว (`ModerationEffect`)** ฟังก์ชันที่เปลี่ยนสิ่งที่สาธารณะเห็นคืน jsonb `{ report, promote, demote }` คือสัญญาณสำหรับ Realtime และรายการไฟล์ที่ต้องย้ายระหว่าง bucket API มีตัวช่วยเดียว `applyEffect` ที่ย้ายไฟล์ (ล้มเหลวลองอีกหนึ่งครั้ง แล้ว log) และ broadcast — แบบเดียวกับ `merge` ของแผน 4
- **ไฟล์รูปตามการมองเห็น:** ไฟล์อยู่ใน `photos-public` ก็ต่อเมื่อเรื่องนั้นสาธารณะ (`open`/`fix_claimed`/`resolved`) และความคิดเห็นนั้น `visible` อนุมัติ → ย้ายจาก `photos-private/{uploader}/{photo}.webp` ไป `photos-public/{report}/{photo}.webp` · ซ่อน → ย้ายกลับ `photos-private` ที่พาธเดิม · คืน → ย้ายไป `photos-public` อีกครั้ง ทั้งหมดรวม `_thumb`
- **เว็บ:** แผงรายละเอียดได้ปุ่ม "แจ้งว่าแก้แล้ว" และเมนู ⋯ (รายงาน, คัดลอกลิงก์, และ "ซ่อนเรื่องนี้" สำหรับแอดมิน) หน้า `/admin` เป็นหน้าเดียวที่มี 5 แท็บ (`?tab=`) และ guard ที่รอ profile โหลดเสร็จก่อนตัดสิน API ตรวจสิทธิ์แอดมินซ้ำทุกคำขอ

## การตัดสินใจที่ผู้เขียนแผนเลือกเอง (เจ้าของค้านได้ก่อนลงมือ)

สเปกเงียบหรือกำกวมในจุดต่อไปนี้ แผนเลือกไว้แบบนี้:

1. **ซ่อนแล้วไฟล์รูปต้องเปิดจาก URL ไม่ได้** ตอนซ่อนเรื่อง (หรือความคิดเห็นที่มีรูป) API ย้ายไฟล์กลับไป `photos-private` ที่พาธเดิม และตอนคืนก็ย้ายกลับ ถ้าไม่ย้าย รูปที่ถูกรายงานเพราะละเมิดความเป็นส่วนตัวจะยังเปิดได้จากลิงก์ที่เคยแชร์ ผลพลอยได้คืองานค้าง "`/me/reports` เสีย `thumb_url` ของเรื่องที่ถูกซ่อน" หายไปเอง เพราะสถานะกับ bucket ตรงกันเสมอ (เรื่องที่ไม่สาธารณะ → ไฟล์อยู่ `photos-private` → signed URL ใช้ได้) ราคาที่จ่าย: ถ้าย้ายไฟล์ล้มเหลวสองครั้ง สถานะใน DB เปลี่ยนแล้วแต่ไฟล์ยังอยู่ที่เดิม (log ไว้ แก้ด้วยมือ เหมือน `merge` ของแผน 4)
2. **รูปหลังแก้ไม่สาธารณะจนกว่าแอดมินยืนยัน** รูปที่แนบตอน "แจ้งว่าแก้แล้ว" ผูกกับเรื่องเป็น `kind = 'claim'` อยู่ใน `photos-private/{claimant}/{photo}.webp` ตอนยืนยันจึงเปลี่ยนเป็น `kind = 'after'` และย้ายไป `photos-public/{report}/{photo}.webp` (หลักข้อ 5 ของ `PRODUCT.md`: ไม่มีอะไรสาธารณะก่อนแอดมินอนุมัติ) ข้อมูลเดโมของเรื่อง `fix_claimed` จึงเปลี่ยนจากรูป `after` สาธารณะเป็นคำขอ `pending` ที่มีรูป `claim` ส่วนตัว (`check-seed.sh` ปรับตาม)
3. **ซ่อนอัตโนมัติเมื่อสมาชิก 3 คนที่ต่างกันรายงานเป้าหมายเดียวกัน** ใช้กับทั้งเรื่องและความคิดเห็น (สเปก 6.2 พูดถึงเรื่องอย่างเดียว แต่ความคิดเห็นสาธารณะทันทีโดยไม่ผ่านแอดมินจึงเสี่ยงกว่า) สมาชิกหนึ่งคนมีรายงานที่ `open` ต่อเป้าหมายหนึ่งได้รายการเดียว รายงานซ้ำไม่ error แต่ไม่นับเพิ่ม (คนเดียวกดสามครั้งจึงซ่อนไม่ได้) บันทึกลง `moderation_log` ด้วย `admin_id = null` (= ระบบ) จึงต้องปลด `not null` ของคอลัมน์นี้
4. **ตำแหน่งตอนอนุมัติมี 4 แบบ:** `keep` (ตามเดิม), `exact` (ใช้พิกัดจริง = ปิดการเลื่อน), `fuzz` (สุ่มเลื่อนใหม่ไม่เกิน 150 ม.), `point` (แอดมินปักเอง ต้องอยู่ในไทยและห่างพิกัดจริงไม่เกิน 1,000 ม. — กันพิมพ์ผิด) กติกาความปลอดภัย: ถ้าหมวดสุดท้ายเป็น `hazard` และใช้ `keep` ขณะที่ `public_location` ยังเท่ากับพิกัดจริง (เช่นแอดมินเปลี่ยนหมวดเป็น hazard) ระบบเลื่อนให้อัตโนมัติ มีแต่ `exact` ที่เปิดเผยพิกัดจริงของ hazard ได้ เพราะเป็นการเลือกตรงๆ ของแอดมิน
5. **เหตุผลการปฏิเสธ:** เก็บเป็นคีย์ใน `REJECT_REASONS` ถ้าเลือก `other` และพิมพ์หมายเหตุ (≤ 200 ตัวอักษร) จะเก็บหมายเหตุแทนคีย์ หน้า `/me` แสดงตามที่เขียนอยู่แล้ว (`rejectReasonText`) ปฏิเสธได้เฉพาะเรื่อง `pending_review` (เรื่องที่สาธารณะแล้วใช้ "ซ่อน")
6. **คืนสถานะเดิมหลังซ่อน:** เพิ่มคอลัมน์ `reports.hidden_from` เก็บสถานะก่อนซ่อน "คืน" กลับไปสถานะนั้นได้ (ทั้งที่แอดมินซ่อนเองและที่ระบบซ่อนอัตโนมัติ) แท็บ "ถูกรายงาน" มีส่วน "ซ่อนอยู่" พร้อมปุ่มคืน ถ้าเรื่อง `fix_claimed` ถูกซ่อน คำขอแจ้งแก้ยังรออยู่ แต่ไม่ขึ้นคิวจนกว่าจะคืน
7. **สัญญาณ Realtime มีสถานะ `hidden` ได้:** เพิ่ม `LiveSignal` (ขยาย `ReportSignal` ด้วย `'hidden'`) ใช้เฉพาะ broadcast และ `RealtimeService` แผนที่และแผงที่เปิดอยู่จึงเอาเรื่องที่ถูกซ่อนออกทันที ส่วน `ReportSignal` ที่ตอบจาก route ของสมาชิกไม่เปลี่ยน
8. **endpoint ที่เพิ่มจากตารางในสเปก 6:** `GET /admin/counts` (ตัวเลขบนหัวแท็บ), `GET /admin/users`, `GET /admin/log`, `POST /admin/hide`, `POST /admin/restore`, และ `type=hidden` ใน `GET /admin/queue` คิว `flags` รวมเป็นหนึ่งรายการต่อเป้าหมาย และ `POST /admin/flags/:id/resolve` ใช้กับรายงาน `open` ทุกรายการของเป้าหมายเดียวกัน แก้ตารางในสเปกตอนปิดงาน
9. **แบน:** แบนบัญชีผู้ดูแล (รวมตัวเอง) ไม่ได้ (`cannot_ban_admin`) · แบนจากหน้าผู้ใช้ไม่ซ่อนเนื้อหาเดิม ส่วน `resolve` แบบ `ban` = ซ่อนเป้าหมาย + แบนเจ้าของเป้าหมาย · เรื่อง `pending_review` ของคนที่ถูกแบนยังอยู่ในคิวให้ปฏิเสธได้
10. **โควตาใหม่:** `RATE_LIMIT_FIX_CLAIMS_PER_DAY` (10) และ `RATE_LIMIT_FLAGS_PER_DAY` (20) ตามสเปก 6.2 นับย้อนหลัง 24 ชั่วโมง หมายเหตุของการแจ้งแก้และการรายงานไม่ผ่านตัวกรองคำหยาบ เพราะมีแต่แอดมินที่เห็น
11. **งานค้างจากแผน 4 (`find_duplicates` / `p_limit`):** ปิดตอนนี้เลยแม้ยังไม่เปิดฟังก์ชันให้ใช้กว้างขึ้น: รัศมีถูกบีบไว้ 0–200 ม. และ `p_limit` ที่เป็น null นับเป็น 0 (ทุกคำขอถูก `rate_limited`) ในทุกฟังก์ชันที่มีโควตา — ใช้ `coalesce(p_limit, 0)`
12. **หน้าแอดมินมีแผนที่ MapLibre ได้แค่ตัวเดียว** (ของเรื่องที่กำลังตรวจ) เพื่อไม่ให้มี WebGL context หลายชุด ให้ `/impeccable shape` เลือกว่าคิวตรวจเป็นแบบ "ทีละเรื่อง" หรือ "รายการ + แผงตรวจ" ภายใต้ข้อนี้

2. **ซ่อนแล้วยังเปิดรูปได้จากลิงก์:** หลังซ่อนเรื่องหรือความคิดเห็นที่มีรูป URL สาธารณะเดิมของรูปเต็มและ `_thumb` ต้องไม่ตอบ 200 หลังคืนต้องกลับมา 200 และ `/me/reports` ของผู้แจ้งยังได้ `thumb_url` ที่โหลดได้ระหว่างถูกซ่อน (เทสต์ใน Task 3, 5, 8)
