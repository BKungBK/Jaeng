## การตัดสินใจที่ผู้เขียนแผนเลือกเอง (เจ้าของค้านได้ก่อนลงมือ)

1. **`appId` = `th.jaeng.app`, ชื่อแอป "แจ้ง"** (ตอนนี้เป็นค่าเริ่มต้นของ starter `io.ionic.starter` / `web`)
2. **CORS ที่ Caddy ไม่ใช่ `CapacitorHttp`:** `CapacitorHttp` ครอบ `fetch` แล้วมีปัญหากับ multipart ของการอัปโหลดรูป จึงให้ Caddy ตอบ `Access-Control-Allow-Origin: http://localhost` เฉพาะ origin ของแอป ใช้กับ `/api` ส่วน `/sb` ตรวจก่อนว่า Kong ตอบเองแล้ว (ห้ามซ้ำสองชั้น)
3. **ที่อยู่เริ่มต้นของ APK มาจากไฟล์ `server.json` ที่ `build-apk.sh` เขียนลง bundle หลัง `ng build`** (ไม่ผูกกับการ build เว็บ) ผู้ใช้แก้ในแอปได้ภายหลัง ค่าที่แก้เก็บใน `@capacitor/preferences` และชนะ `server.json`
4. **เปลี่ยนที่อยู่เซิร์ฟเวอร์แล้ว `location.reload()`** แทนการสร้าง client ใหม่กลางทาง (Supabase client, realtime และ session ผูกกับ URL เดิม)
5. **ไม่ใช้ปุ่มสลับผู้ใช้เดโมใน APK:** API ตอบ quick login เฉพาะ Host `localhost`/`127.0.0.1` จึงปิดเองเมื่อเปิดผ่าน `http://<IP>:8000` ล็อกอินบนมือถือใช้ OTP 6 หลัก โดยอ่านรหัสจาก Mailpit บนคอม (`http://localhost:54324`) ส่วน `additional_redirect_urls` ไม่ต้องแก้เพราะ OTP ไม่ใช้ redirect
6. **รหัสผ่านเดโมสุ่ม** (ข้อกำหนดจาก roadmap แผน 7): `gen-env.sh` เก็บ `DEMO_PASSWORD` เดิมไว้ถ้าไม่ใช่ค่าเก่า `jaeng-demo-1234` ไม่เช่นนั้นสุ่มใหม่ ผู้ใช้เดโมต้องสร้างใหม่ด้วย `reset-db.sh` หนึ่งครั้ง
7. **ปุ่ม back ใช้ `Platform.backButton` ของ Ionic** (overlay=100, router=0) เพิ่มสองตัวจัดการ: หน้า `/report` ที่ priority 50 และออกจากแอปที่ priority -1 ไม่ใช้ `App.addListener('backButton')` เพราะมันปิด handler เริ่มต้นทั้งหมดของ Ionic
8. **กล้อง/คลังใน APK ใช้ `@capacitor/camera`** (`Camera.getPhoto` / `Camera.pickImages`) ไม่ตั้ง `correctOrientation` เพื่อให้ EXIF orientation อยู่ในไฟล์ให้ `compressImage` อ่านเหมือนเว็บ ถ้ารูปไม่มี GPS ใน EXIF ขั้นปักหมุดตกไปใช้ `DeviceService.currentPosition()` ตามเดิม (ไม่ต้องแก้ตรรกะนั้น)

**Interfaces:**
- Consumes: Task 1 `setServerOrigin`, `platform.isNative`
- Produces ใน `ServerConfigService`:
  - `readonly native: boolean`, `readonly address: Signal<string>` (`''` บนเว็บ)
  - `init(): Promise<void>` — native: อ่าน Preferences key `server` ถ้าไม่มีอ่าน `server.json` (`{ "server": "http://…" }`) ที่รากของ bundle ถ้าไม่มีอีกก็ปล่อยว่าง แล้ว `setServerOrigin`; เว็บ: ไม่ทำอะไร ไม่โยนเด็ดขาด
  - `check(raw: string, timeoutMs = 5000): Promise<ServerCheck>` โดย `export type ServerCheck = { ok: true; address: string } | { ok: false; reason: 'invalid' | 'unreachable' | 'notJaeng' }` — `invalid` เมื่อ `normalizeServerUrl` ได้ null, `unreachable` เมื่อ fetch ล้ม/หมดเวลา, `notJaeng` เมื่อ `/api/health` ไม่ใช่ JSON ที่มี `ok` เป็น boolean (API ตอบ `{ok, db}`; 503 ที่ `ok:false` ยังนับว่าเป็นแจ้ง เพียงแต่ DB ล่ม ให้ `ok: true` เพราะเซิร์ฟเวอร์ถูกตัว)
  - `save(raw: string): Promise<void>` — `check` แล้วบันทึก Preferences แล้ว `location.reload()`; ถ้าไม่ ok ให้โยน `ServerCheckError` ที่มี `reason`
  - `export function normalizeServerUrl(raw: string): string | null` — trim, ไม่มี scheme → เติม `http://`, รับเฉพาะ `http:`/`https:`, ต้องมี hostname, ตัด path/query/hash และ `/` ท้าย ได้รูป `scheme://host[:port]`
