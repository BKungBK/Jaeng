## 1. แอปนี้คืออะไร และทำไปทำไม

**แจ้ง** คือเว็บแอปให้คนทั่วไปแจ้งปัญหาในชุมชน เช่น ถนนพัง ไฟดับ ท่อตัน ขยะ หรือกิ่งไม้พาดสายไฟ คนแจ้งถ่ายรูปแล้วปักหมุด เรื่องนั้นจะขึ้นบนแผนที่ประเทศไทยเป็น **สัญญาณไฟแบบ Bat-Signal** คือมีลำแสงพุ่งขึ้นจากจุดที่ปักหมุด ไปจบที่วงกลมใหญ่ที่มีไอคอนหมวดอยู่ข้างใน คนในละแวกนั้นกด "เจอเหมือนกัน" แสดงความคิดเห็น และเห็นได้ว่าเรื่องนั้นแก้แล้วหรือยัง

ชื่อ "แจ้ง" เป็นการเล่นคำ เพราะแปลได้ทั้ง *แจ้งเรื่อง* และ *สว่าง* (เหมือนคำว่าฟ้าแจ้ง) ซึ่งตรงกับภาพลำแสงที่ส่องขึ้นจากจุดที่มีปัญหา (**ตัดสินแล้ว**: ใช้ชื่อ "แจ้ง" คำเดียว)

**ทำไปทำไม:** เป็นงานส่งอาจารย์ เป้าหมายคือให้อาจารย์ **เห็นภาพและเข้าใจ** ว่าแอปทำอะไร ใช้งานยังไง และใช้งานได้จริงตั้งแต่ต้นจนจบ ส่วนการหาผู้ใช้จริง (ปัญหา cold start) เจ้าของจะเติมข้อมูลเองทีหลัง

### 1.1 ความสำเร็จหน้าตาเป็นยังไง

ในวันเดโม เจ้าของต้องทำสิ่งเหล่านี้ให้อาจารย์ดูบนเครื่องตัวเองได้ครบในรอบเดียว ไม่มีจุดที่ต้องบอกว่า "อันนี้ยังไม่ได้ทำ":

1. เปิดแอป เห็นแผนที่ไทยแบบภาพประกอบมีลำแสงกระจายทั่วประเทศ แล้วซูมเข้าจนกลายเป็นแผนที่ถนนจริง
2. แจ้งเรื่องใหม่จากมือถือภายใน 3 แตะ (ถ่ายรูป → เลือกหมวด → ยืนยันตำแหน่ง)
3. สลับไปเป็นแอดมิน อนุมัติเรื่องนั้น แล้วลำแสงใหม่ขึ้นบนแผนที่
4. ผู้ใช้อีกคนกด "เจอเหมือนกัน" และแสดงความคิดเห็น ลำแสงสูงขึ้น
5. มีคนกด "แจ้งว่าแก้แล้ว" แล้วลำแสงจางลง แอดมินยืนยัน ลำแสงดับเหลือเครื่องหมายถูก
6. สลับภาษาไทย/อังกฤษได้ และใช้งานบนมือถือได้ดีพอๆ กับบนคอม
7. ทำทั้งหมดนี้บน **มือถือ Android จริงที่ติดตั้งแอปจากไฟล์ APK** โดยใช้ GPS และกล้องของเครื่องได้ (**ตัดสินแล้ว**)

**ขอบเขต (ตัดสินแล้ว):** ทำครบทุกเฟสในหัวข้อ 12 โดยไม่ตัดอะไรออกเพราะเวลา และวันเดโมมีอินเทอร์เน็ต

### 1.2 เป้าหมาย (Goals)

- แจ้งเรื่องได้ **ง่ายมาก** (หัวใจของแอป): จำเป็นแค่ 3 ขั้น ที่เหลือเพิ่มทีหลังได้
- มองแผนที่แล้ว **รู้ทันที** ว่าตรงไหนมีเรื่องอะไร และอันตรายแค่ไหน **โดยไม่ต้อง hover** เพราะมือถือ hover ไม่ได้
- เรื่องที่ยังไม่ถูกแก้ต้อง **เห็นชัด** ว่าค้างมานานแค่ไหน เพื่อสร้างแรงกดดันทางสังคม
- ทุกเรื่องและทุกการปิดเรื่อง **ผ่านแอดมินก่อน** กันการแจ้งมั่ว
- คนแจ้ง **ปิดชื่อตัวเองได้** แต่ระบบหลังบ้านยังรู้ว่าเป็นใคร
- ดูน่าเชื่อถือและอบอุ่น โทน pastel
- ใช้ได้ทั้งมือถือและเดสก์ท็อป (**ตัดสินแล้ว**: ให้น้ำหนักเท่ากัน) และมีทั้งภาษาไทยและอังกฤษ (**ตัดสินแล้ว**)

### 1.3 สิ่งที่ไม่ทำในรอบนี้ (Non-goals)

- **เบลอใบหน้าและป้ายทะเบียนอัตโนมัติ** เลื่อนไปทำทีหลัง (**ตัดสินแล้ว**) แต่ต้องเว้นที่ไว้ในระบบ ดูหัวข้อ 9
- **เปิดให้คนนอกเข้ามาลอง** ทำเป็นขั้นสุดท้าย (**ตัดสินแล้ว**) และต้องทำหลังจากเบลอรูปเสร็จแล้วเท่านั้น
- ขึ้นเว็บจริง (โดเมน/โฮสติ้ง): ระบบรันบนเครื่องอย่างเดียว
- ระบบหน่วยงาน (เทศบาล/อบต.) เพราะผู้ใช้หลักคือคนทั่วไป (**ตัดสินแล้ว**) จะมีแค่บทบาทแอดมิน
- ขึ้น Play Store หรือทำแอป iOS: ทำแค่ **APK สำหรับ Android ที่ติดตั้งเองได้** (ห่อโค้ดเว็บเดิมด้วย Capacitor) และเว็บเดียวกันยังเปิดในเบราว์เซอร์และติดตั้งเป็น PWA ได้
- การแจ้งเตือนแบบ push, แชต, ระบบคะแนนหรือรางวัล
- แปลเนื้อหาที่ผู้ใช้เขียนเอง: แปลแค่ UI กับชื่อหมวด

### 1.4 สิ่งที่ถือว่าล้มเหลวแม้ระบบจะทำงาน (Anti-goals)

- แจ้งเรื่องแล้วยุ่งยาก ต้องกรอกฟอร์มยาว
- แผนที่รกจนอ่านไม่ออก หรือต้อง hover ก่อนถึงจะรู้ว่าจุดนั้นคืออะไร
- สื่อความหมายด้วย **สีอย่างเดียว** (คนตาบอดสีอ่านไม่ได้)
- เปิดให้คนนอกเห็นรูปที่มีใบหน้าหรือป้ายทะเบียนโดยยังไม่ได้เบลอ
- แอปกลายเป็นที่ประจานหรือใส่ร้ายบุคคล
- ดูมืดแบบเกม หรือดูเย็นชาแบบระบบราชการ

## 3. ประสบการณ์ผู้ใช้ (UX)

### 3.1 บทบาทผู้ใช้

| บทบาท | ทำอะไรได้ |
|---|---|
| ผู้เยี่ยมชม (ไม่ล็อกอิน) | ดูแผนที่ ดูรายละเอียด ดูความคิดเห็น ค้นหาและกรอง |
| สมาชิก (ล็อกอิน) | ทุกอย่างของผู้เยี่ยมชม และ แจ้งเรื่อง, กด "เจอเหมือนกัน", แสดงความคิดเห็น, แจ้งว่าแก้แล้ว, รายงานเนื้อหาไม่เหมาะสม, ดู "เรื่องของฉัน" |
| แอดมิน | ทุกอย่างของสมาชิก และ ตรวจ/อนุมัติ/ปฏิเสธเรื่องใหม่, ยืนยันการแก้, จัดการรายงาน, ซ่อนเนื้อหา, แบนผู้ใช้ |

### 3.2 หน้าแรก: จากโลกสู่บ้านตัวเอง

ลำดับตอนเปิดแอป (ต้นแบบมีแค่ขั้น 2–4 ส่วนขั้น 1 ยังไม่ได้ทำ):

1. ~~**โลก (globe)** หมุนเข้าหาประเทศไทย~~ ตัดออกในแผน 2b (**ตัดสินแล้ว** 2026-10-17: "เอาแผนที่อื่นออกตอนซูมให้เหลือแค่ไทย") ตอนนี้แผนที่เป็น mercator ซูมออกได้แค่พอเห็นทั้งประเทศ และจุดกลางกล้องถูกกันไว้ในไทยบวกขอบเผื่อราว 2 องศา ทุกระดับซูมนอกไทยเป็นทะเล cel-shading ที่มีอนิเมชัน (คลื่น ฟอง ลายแสง caustics และประกายแสง ตามภาพอ้างอิงที่เจ้าของส่งมา)
2. **ภาพประกอบแผนที่ไทย** (ระดับประเทศ) (**ตัดสินแล้ว**: "แบบตามภาพเลย" แล้วซูมเข้าได้) ภาพอ้างอิงคือโปสเตอร์ "Thailand ดินแดนแห่งความสุข" ที่เจ้าของแนบในแชตเดิม รายละเอียดดูหัวข้อ 3.2.1
3. ถ้าผู้ใช้อนุญาตให้ใช้ตำแหน่ง แผนที่จะ **บินเข้าหาตำแหน่งผู้ใช้** อัตโนมัติ ถ้าไม่อนุญาตก็ค้างที่ภาพรวมประเทศ
4. ยิ่งซูมเข้า ภาพประกอบยิ่ง **จางลงจนกลายเป็นแผนที่ปกติ** ที่เห็นถนนและอาคาร

ระดับซูม (MapLibre zoom) ที่ใช้ (**ผู้ออกแบบเลือก**, ปรับได้):

| zoom | สิ่งที่เห็น |
|---|---|
| ทุกระดับ | หน้ากากทะเลซ่อนประเทศอื่น (แผน 2b) |
| ≤ 6 | ภาพประกอบเต็ม 100% และ beacon รวมเป็นวงตัวเลข (cluster) |
| 6 – 8 | ภาพประกอบค่อยๆ จางจาก 100% เป็น 0% แผนที่ปกติค่อยๆ โผล่ |
| 8 – 12 | แผนที่ปกติ beacon ยังรวมกลุ่มตามความหนาแน่น |
| ≥ 12 | แยกเป็นลำแสงทีละเรื่อง พร้อมป้ายชื่อสั้น |

#### 3.2.1 หน้าตาภาพประกอบ (ตามภาพอ้างอิง)

ลักษณะของภาพอ้างอิงที่ต้องเก็บให้ได้:

- **แผ่นดินเป็นก้อนหนาแบบโมเดลของเล่น 3 มิติ** ด้านข้างเป็นดินสีน้ำตาลไล่เข้ม และขอบบนสีครีม
- **สีตามภาค:** เหนือ กลาง ตะวันออก ตะวันตก และใต้เป็นเขียวสด ส่วนอีสานเป็นส้ม มีเส้นแบ่งจังหวัดบางๆ บนผิวแผ่นดิน
- **ทะเลสีฟ้าสด** มีคลื่นลายเบาๆ และ**เมฆขาวฟู**ลอยตามขอบจอ
- **สัญลักษณ์ประจำพื้นที่วางบนแผ่นดินแบบ 3D ตัวเล็ก** ตัวอย่าง:
  - เหนือ: ภูเขา วัด ดอกไม้
  - อีสาน: พญานาค ไดโนเสาร์ (ขอนแก่น) ช้าง ปราสาท
  - กลาง: วัด/เจดีย์ (อยุธยา กรุงเทพ)
  - ตะวันออก: ชายหาด ร่มชายหาด
  - ใต้: เกาะ ต้นมะพร้าว เรือหางยาว
- **ยานพาหนะ:** รถไฟวิ่งตามแนวเส้นทางรถไฟสายหลัก เครื่องบิน 2 ลำบินผ่าน เรือสำราญและเรือใบในทะเล
- **ป้ายชื่อจังหวัด:** ตัวหนาสีขาวขอบเข้ม แสดงชุดเดียวกับภาพอ้างอิง (เชียงใหม่ พิษณุโลก นครสวรรค์ ขอนแก่น นครราชสีมา อุบลราชธานี พระนครศรีอยุธยา กรุงเทพมหานคร กาญจนบุรี ชลบุรี ระยอง สุราษฎร์ธานี ภูเก็ต สงขลา ปัตตานี)
- **ตกแต่งมุมจอ:** เข็มทิศมุมล่างขวา และหัวเรื่อง "แจ้ง" ใช้ฟอนต์ตัวหนาแบบเดียวกับหัวเรื่องในภาพ (แทนคำว่า Thailand)

วิธีทำ (**ผู้ออกแบบเลือก**): ไม่ใช้ภาพแรสเตอร์ทั้งผืน เพราะภาพวาดไม่ตรงพิกัดจริง พอจางเข้าหาแผนที่ปกติแล้วจะเหลื่อมกัน ให้ประกอบจากชิ้นที่วางบนพิกัดจริงแทน:

1. **แผ่นดิน:** ใช้ GeoJSON ประเทศและจังหวัดจริง ทำความหนาด้วยชั้น `fill-translate` 3–4 ชั้น และระบายสีตามภาค (หัวข้อ 4.4)
2. **สัญลักษณ์ 3D:** ใช้ชุด **Microsoft Fluent Emoji 3D** (ไลเซนส์ MIT) เช่น 🛕 🐘 🐉 🦕 🏯 ⛰️ 🌸 🏝️ 🌴 ⛱️ 🚤 🛳️ ⛵ 🚆 ✈️ 🧭 ☁️ หน้าตาเป็นของเล่น 3D แบบเดียวกับภาพอ้างอิง นำมาทำ sprite sheet ให้ MapLibre วางเป็น symbol layer ตามพิกัด สัญลักษณ์จะย่อขยายตามซูมและจางไปพร้อมภาพประกอบ
3. **ของเคลื่อนไหว:** เมฆ เครื่องบิน และรถไฟเป็น HTML/Canvas overlay ที่เคลื่อนที่ช้าๆ (~~ปิดเมื่อ `prefers-reduced-motion`~~ ยกเลิกตามคำสั่งเจ้าของ 2026-10-17: แอปไม่อ่านค่านี้เลย)
4. **ภายหลัง (ถ้าอยากให้ใกล้ภาพมากขึ้น):** เจ้าของสร้างภาพสัญลักษณ์แต่ละชิ้นเองด้วยเครื่องมือสร้างภาพ แล้วนำมาแทน sprite ได้ โดยไม่ต้องแก้โค้ด

แถบสถานะเล็กมุมจอบอกว่ากำลังดูระดับไหน เช่น "ภาพรวมประเทศ: วงตัวเลข = จำนวนเรื่องในพื้นที่ ซูมเข้าเพื่อดูแต่ละเรื่อง" ตามต้นแบบ

### 3.3 สัญญาณไฟ (Beacon)

ส่วนประกอบหนึ่ง beacon (ตามต้นแบบ):

- **จุดฐาน** เป็นวงเล็กสีตามระดับ วางตรงพิกัดจริง
- **วงพัลส์** แผ่ออกจากฐานเป็นวงรี (เหมือนแสงตกกระทบพื้น)
- **ลำแสง** เป็นกรวยไล่สีจากฐานขึ้นไป ความสูงขึ้นกับจำนวน "เจอเหมือนกัน" แบบ log: `min(260, 60 + 36 × log2(1 + n))` px (n=0 → 60, 1 → 96, 3 → 132, 10 → 185, 40 → 253) (**ผู้ออกแบบเลือก**: เปลี่ยนจากสูตรเส้นตรงในต้นแบบ เพราะกด +1 แล้วต้องเห็นลำแสงสูงขึ้นชัดในฉากเดโม ส่วนแอนิเมชันตอนลำแสงสูงขึ้นใช้ 400ms)
- **วงหัวลำแสง** วงกลมขาวขอบสีตามระดับ มีไอคอนหมวดอยู่ข้างใน และมีเครื่องหมายรูปทรงของระดับที่มุมขวาล่าง
- **ป้ายชื่อสั้น** เหนือวง เพื่อให้รู้ว่าจุดนั้นคืออะไรโดยไม่ต้อง hover (**ตัดสินแล้ว**: ต้องรู้คร่าวๆ ได้เลย)

**ระดับอันตราย 4 ระดับ** (**ตัดสินแล้ว**) ใช้ 3 อย่างพร้อมกัน คือ สี รูปทรง และความเร็วพัลส์ เพื่อให้คนตาบอดสีอ่านได้:

| ระดับ | ชื่อ (TH / EN) | สี | รูปทรง | พัลส์ | วงพัลส์ |
|---|---|---|---|---|---|
| 0 | ทั่วไป / Minor | `#8FD3B6` มิ้นต์ | ● | 3 วินาที | 1 วง |
| 1 | ควรระวัง / Caution | `#F6D983` เหลืองนวล | ▲ | 2.4 วินาที | 1 วง |
| 2 | อันตราย / Danger | `#F4A582` พีช | ◆ | 1.6 วินาที | 2 วง |
| 3 | วิกฤต / Critical | `#E57373` แดงอ่อน | ⚠ | 1 วินาที | 2 วง |

เรื่องระดับ 3 แสดงกล่องเตือนในหน้ารายละเอียดว่า "ระบบนี้ไม่ใช่ช่องทางฉุกเฉิน หากมีอันตรายทันที โทร 191 / 199 / 1669"

**สถานะแสดงด้วยรูปร่างของลำแสง ไม่ใช้สี** (สีใช้บอกระดับอย่างเดียว):

| สถานะ | หน้าตา |
|---|---|
| ยังไม่ได้แก้ (`open`) | ลำแสงเต็ม วงพัลส์ทำงาน และมีป้าย "ค้างมา N วัน" ถ้าค้างเกิน 30 วัน ป้ายจะเข้มขึ้นเป็น "ค้างนาน" |
| รอตรวจว่าแก้แล้ว (`fix_claimed`) | ลำแสงจางเหลือ 28% วงหัวเป็นเส้นประ และไม่มีพัลส์ |
| แก้แล้ว (`resolved`) | ไม่มีลำแสง วงเปลี่ยนเป็นสีมิ้นต์พร้อมเครื่องหมายถูก และหายจากแผนที่หลัง 30 วัน (แต่ยังค้นเจอในรายการ: แผน 6 ให้ `/list` แสดงเมื่อเปิด "แสดงเรื่องที่แก้แล้ว" และลิงก์ตรงเปิดได้ทุกอายุ) |

**วงรวมกลุ่ม (cluster)** ตอนซูมไกล เป็นวงขาวที่มีตัวเลขจำนวนเรื่อง สีขอบใช้ **ระดับสูงสุด** ในกลุ่มนั้น พอกดวงจะบินซูมเข้าไป

**ป้ายชื่อชนกัน:** ถ้ามีป้ายในจอเกิน 12 ป้าย ให้แสดงเฉพาะเรื่องที่ "เจอเหมือนกัน" มากที่สุด ส่วนป้ายอื่นซ่อนไว้ (**ผู้ออกแบบเลือก**)

### 3.4 Hover, แตะ และรายละเอียด

- **เดสก์ท็อป:** hover ที่วงจะขึ้น tooltip ที่มีหัวข้อ ระดับ สถานะ และจำนวน "เจอเหมือนกัน" พร้อม **รูปตัวอย่าง** (**ตัดสินแล้ว**: รูปขึ้นตอน hover ไม่มีรูปจิ๋วบนแผนที่) ถ้าคลิกจะเปิดแผงรายละเอียดด้านขวากว้าง 380px
- **มือถือ:** แตะวงจะเปิด bottom sheet ขึ้นมาประมาณ 64% ของจอ ปัดขึ้นเพื่อดูแบบเต็มจอ
- **แผงรายละเอียด** มีเนื้อหาเรียงตามนี้:
  1. แกลเลอรีรูป (ก่อนแก้/หลังแก้)
  2. หัวข้อ
  3. แท็ก: ระดับ, หมวด, สถานะ และ "ค้างมา N วัน"
  4. คำอธิบาย
  5. ผู้แจ้งและเวลา (แสดงเป็น "ผู้ใช้นิรนาม" ถ้าผู้แจ้งเลือกปิดชื่อ)
  6. ปุ่ม **เจอเหมือนกัน · N** (กดซ้ำเพื่อยกเลิก)
  7. ปุ่ม **แจ้งว่าแก้แล้ว** (เรื่อง `fix_claimed` แสดงข้อความ "มีคนแจ้งว่าแก้แล้ว รอผู้ดูแลตรวจ" แทน) ฟอร์มแจ้งแก้และฟอร์มรายงานเปิดแทนแถวปุ่มในแผงเดียวกัน
  8. เมนู ⋯: คัดลอกลิงก์, รายงานเนื้อหาไม่เหมาะสม และ (แอดมินเท่านั้น) ซ่อนเรื่องนี้ · ความคิดเห็นแต่ละรายการมีปุ่มรายงานของตัวเอง
  9. ความคิดเห็น พร้อมช่องพิมพ์
- แต่ละเรื่องมี URL ของตัวเอง `/r/:id` เปิดลิงก์มาแล้วแผนที่บินไปที่จุดนั้นและเปิดแผงให้เลย

### 3.5 การแจ้งเรื่อง (หัวใจของแอป)

(**ตัดสินแล้ว**: 3 แตะ, ต้องมีรูป, GPS อัตโนมัติและปักเองได้, ผ่านแอดมินก่อน)

ปุ่มลอย **"＋ แจ้ง"** อยู่มุมล่างขวาเสมอ ถ้ายังไม่ล็อกอินจะเปิดหน้าล็อกอินก่อนแล้วค่อยกลับมาที่ขั้นแจ้ง

| ขั้น | หน้าจอ | หมายเหตุ |
|---|---|---|
| 1 | **รูป**: ถ่ายรูปหรือเลือกจากคลัง ใส่ได้ 1–4 รูป | บีบอัดในเบราว์เซอร์ก่อนอัปโหลด และอ่านพิกัด GPS จาก EXIF ถ้ามี |
| 2 | **หมวด**: ตารางไอคอนใหญ่ 8 หมวด | หมวดจะกำหนดระดับอันตรายเริ่มต้นให้ |
| 3 | **ตำแหน่ง**: แผนที่มีหมุดกลางจอ ลากแผนที่เพื่อเลื่อนหมุดได้ | ลำดับค่าเริ่มต้น: พิกัด EXIF → GPS ของเครื่อง → กลางจอเดิม |
| — | **ส่ง** | ก่อนส่ง ระบบตรวจหาเรื่องซ้ำ (หัวข้อ 3.6) |

ช่องเสริมที่ไม่บังคับ อยู่ใต้ปุ่มส่งแบบพับเก็บไว้ ("เพิ่มรายละเอียด"):

- หัวข้อ: ถ้าเว้นว่าง ระบบตั้งให้เป็น "{หมวด} {อำเภอ} {จังหวัด}" (หาอำเภอจากพิกัดในฐานข้อมูลเอง ดูหัวข้อ 4.2)
- คำอธิบาย ไม่เกิน 1000 ตัวอักษร
- ระดับอันตราย: ปรับจากค่าเริ่มต้นได้
- แท็กที่ผู้ใช้เพิ่มเอง (หัวข้อ 3.7)
- สวิตช์ **"ไม่แสดงชื่อฉัน"** ค่าเริ่มต้นคือปิด (แสดงชื่อ) (**ผู้ออกแบบเลือก**)

ส่งแล้วขึ้นข้อความ "ส่งแล้ว รอผู้ดูแลตรวจ" เรื่องนั้นจะเห็นใน "เรื่องของฉัน" พร้อมสถานะ แต่ยังไม่ขึ้นบนแผนที่สาธารณะ

**ข้อความกำกับใต้ปุ่มส่ง:** "เล่าที่ปัญหา ไม่ระบุชื่อหรือกล่าวหาบุคคล" (กันความเสี่ยงหมิ่นประมาท, **ตัดสินแล้ว**)

### 3.6 กันเรื่องซ้ำ

ตอนกดส่ง API จะหาเรื่องที่สถานะ `open` หรือ `fix_claimed` **หมวดเดียวกัน ภายในรัศมี 50 เมตร** โดยเทียบกับ `public_location` (ไม่ใช่พิกัดจริง) เพื่อไม่ให้ผลกันซ้ำของเรื่อง hazard เผยพิกัดจริง ถ้าเจอจะขึ้นการ์ดถามว่า "เรื่องนี้ใช่ไหม?" พร้อมรูปและหัวข้อ ผู้ใช้เลือกได้สองทาง:

- **"ใช่ กดเจอเหมือนกันแทน"**: ระบบนับ +1 ให้เรื่องเดิม และแนบรูปใหม่เป็นความคิดเห็นในเรื่องนั้น
- **"ไม่ใช่ แจ้งเป็นเรื่องใหม่"**

(**ตัดสินแล้ว**: ตามที่แนะนำ)

### 3.7 หมวดหลักและแท็ก

หมวดหลัก 8 หมวด (**ตัดสินแล้ว**: "โอเค") ที่ผู้ใช้เลือกได้:

| slug | TH | EN | ไอคอน | ระดับเริ่มต้น |
|---|---|---|---|---|
| `road` | ถนน/ทางเท้า | Road & sidewalk | `construction` | 1 |
| `light` | ไฟฟ้า/ไฟส่องสว่าง | Lighting & power | `lightbulb` | 1 |
| `water` | น้ำประปา/ท่อระบาย | Water & drains | `droplet` | 1 |
| `flood` | น้ำท่วม | Flooding | `waves` | 2 |
| `waste` | ขยะ | Waste | `trash2` | 0 |
| `tree` | ต้นไม้ | Trees | `treeDeciduous` | 1 |
| `hazard` | จุดเสี่ยง/ความปลอดภัย | Safety hazard | `triangleAlert` | 2 |
| `other` | อื่นๆ | Other | `mapPin` | 0 |

ไอคอนทุกตัวในแอปเป็น SVG จาก **Lucide** (ISC) และห้ามใช้อิโมจิเลย (**ตัดสินแล้ว** 2026-10-17 โดยเจ้าของ แทน Fluent Emoji 3D) ชื่อในตารางคือชื่อไอคอน Lucide ซึ่งเก็บไว้ในคอลัมน์ `categories.icon` และ `CATEGORY_ICONS` ใน `packages/shared` มี test คอยกันไม่ให้อิโมจิหลุดเข้ามาในโค้ด

**แท็กของผู้ใช้** (**ตัดสินแล้ว**: ผู้ใช้เพิ่มหมวดเองได้ไม่จำกัด เพื่อช่วยค้นหา) แท็กเป็นข้อความอิสระ เช่น `#หน้าโรงเรียน` `#ซอย5` ใส่ได้สูงสุด 5 แท็กต่อเรื่อง ยาวไม่เกิน 30 ตัวอักษร และ autocomplete จากแท็กที่มีคนใช้แล้ว แท็กเป็นส่วนเสริมของหมวดหลัก ไม่ได้แทนหมวด (**ผู้ออกแบบเลือก**) เพราะถ้าให้สร้างหมวดหลักได้ไม่จำกัด สีกับไอคอนบนแผนที่จะไม่มีความหมาย แอดมินลบหรือรวมแท็กที่ไม่เหมาะสมได้

### 3.8 วงจรชีวิตของเรื่อง

```
                (แอดมินปฏิเสธ)
 pending_review ───────────────► rejected
       │ (แอดมินอนุมัติ)
       ▼
     open ◄───────────────────────┐
       │ (ใครก็ได้กด "แจ้งว่าแก้แล้ว")    │ (แอดมินปฏิเสธการแจ้งแก้)
       ▼                          │
  fix_claimed ────────────────────┘
       │ (แอดมินยืนยัน)
       ▼
    resolved

 สถานะใดก็ได้ (ยกเว้น rejected) ──(แอดมินซ่อน / รายงานครบ 3 คน)──► hidden ──(แอดมินคืน)──► สถานะเดิม
```

- **คืน (แผน 5):** `reports.hidden_from` จำสถานะก่อนซ่อน แอดมินคืนได้ทั้งที่ซ่อนเองและที่ระบบซ่อนอัตโนมัติ การคืนถือเป็นการตัดสินของแอดมิน รายงานที่ยังเปิดอยู่ของเป้าหมายนั้นจึงถูกปิดเป็น `dismissed` ด้วย
- **คำขอแจ้งแก้ระหว่างถูกซ่อน:** เรื่อง `fix_claimed` ที่ถูกซ่อน คำขอยังรออยู่ แต่ไม่ขึ้นคิวและตรวจไม่ได้จนกว่าจะคืน

- **แจ้งว่าแก้แล้ว** (**ตัดสินแล้ว**: ใครก็ได้กด แล้วส่งให้แอดมินตรวจ): แนบ "รูปหลังแก้" ได้ (ไม่บังคับ แต่แนะนำ) และใส่หมายเหตุได้ เรื่องหนึ่งมีคำขอที่รอตรวจได้ทีละ 1 คำขอ
- ถ้าแอดมินปฏิเสธการแจ้งแก้ เรื่องจะกลับเป็น `open` และนับวันค้างต่อจากวันที่แจ้งครั้งแรก
- **ไม่ปิดเรื่องอัตโนมัติ** (**ตัดสินแล้ว**: ต้องให้คนรู้ว่ายังไม่แก้) ให้แสดง "ค้างมา N วัน" ไปเรื่อยๆ แทน
- ตอนอนุมัติ แอดมินแก้หมวด ระดับ หัวข้อ และความแม่นของพิกัดได้

### 3.9 หน้าอื่นๆ

| เส้นทาง | หน้า | เนื้อหา |
|---|---|---|
| `/` | แผนที่ | หน้าหลัก ตามหัวข้อ 3.2–3.4 |
| `/r/:id` | แผนที่ + เปิดรายละเอียด | ลิงก์แชร์ได้ |
| `/list` | รายการ | มุมมองแบบรายการของเรื่องในกรอบจอปัจจุบัน เรียงตามใกล้ฉัน/ใหม่สุด/เจอเหมือนกันมากสุด/ค้างนานสุด เป็นทางเลือกที่เข้าถึงได้ง่ายกว่าแผนที่ |
| `/report` | แจ้งเรื่อง | ตามหัวข้อ 3.5 |
| `/me` | ของฉัน | เรื่องที่ฉันแจ้งพร้อมสถานะ (รวมถึงที่ถูกปฏิเสธพร้อมเหตุผล), ตั้งชื่อที่แสดง, ภาษา, ธีม, ออกจากระบบ |
| `/login` | ล็อกอิน | หัวข้อ 6.1 |
| `/about` | เกี่ยวกับ / กติกา | กติกาการแจ้ง (เน้นปัญหา ไม่ใช่ตัวบุคคล), นโยบายข้อมูลส่วนตัวสั้นๆ, เบอร์ฉุกเฉิน |
| `/admin` | แอดมิน | หัวข้อ 3.10 |

**แถบบน** ประกอบด้วย:

- โลโก้ "แจ้ง"
- ช่องค้นหา (ค้นจากหัวข้อและแท็ก หรือค้นชื่อสถานที่เพื่อบินไปที่นั่น)
- ชิปกรอง 4 ระดับ (ตามต้นแบบ)
- ปุ่มตัวกรองเพิ่มเติม (หมวด, สถานะ, แสดงเรื่องที่แก้แล้ว)

**ตัวเลขกำลังใจ** อยู่การ์ดมุมล่างซ้าย เช่น "เดือนนี้แก้แล้ว 12 เรื่อง · ค้างอยู่ 31 เรื่อง" คิดจากพื้นที่ที่อยู่ในจอ (ระดับประเทศ/จังหวัด)

### 3.10 หน้าแอดมิน

แท็บบนหน้า `/admin`:

1. **รอตรวจ**: เรื่องใหม่เรียงจากเก่าสุด แสดงรูปใหญ่ แผนที่เล็ก และข้อมูลผู้แจ้ง (รวมชื่อจริงแม้ผู้แจ้งจะปิดชื่อไว้) มีปุ่ม **อนุมัติ** (พร้อมแก้ช่องต่างๆ ได้) และ **ปฏิเสธ** (ต้องเลือกเหตุผล: ซ้ำ / ไม่ใช่ปัญหาสาธารณะ / เนื้อหาไม่เหมาะสม / ข้อมูลไม่พอ / อื่นๆ)
2. **แจ้งว่าแก้แล้ว**: แสดงรูปก่อนแก้กับหลังแก้เทียบกัน มีปุ่มยืนยันและปฏิเสธ
3. **ถูกรายงาน**: เรื่องหรือความคิดเห็นที่ถูกรายงาน มีปุ่มซ่อน ยกเลิกรายงาน หรือแบนผู้ใช้
4. **ผู้ใช้**: ค้นหา แบน หรือยกเลิกแบน
5. **บันทึก**: ประวัติทุกการกระทำของแอดมิน

แต่ละแท็บมีตัวเลขค้างบนหัว แอดมินใช้งานบนมือถือได้ด้วย

## 4. สถาปัตยกรรม

```
 เบราว์เซอร์ (มือถือ/คอม)
   │  http://localhost:8000   ← จุดเข้าเดียว (single origin)
   ▼
 ┌──────────── Caddy (reverse proxy, Docker) ─────────────┐
 │  /          → web   (Angular + Ionic dev server)       │
 │  /api/*     → api   (Elysia บน Bun)                     │
 │  /sb/*      → Supabase API gateway (Kong :8000 ใน network) │
 └────────────────────────────────────────────────────────┘
        │ อ่าน (supabase-js, RLS)        │ เขียน (fetch + JWT)
        ▼                                ▼
   Supabase (รันด้วย Supabase CLI ใน Docker)  ◄── api ใช้ service role
   Postgres + PostGIS · Auth · Storage · Realtime · Studio · Mailpit
```

### 4.1 หลักการแบ่งหน้าที่ (**ผู้ออกแบบเลือก**)

- **อ่าน: Angular ต่อ Supabase ตรงๆ** ผ่าน supabase-js โดยอ่านจาก view สาธารณะที่ RLS อนุญาตเท่านั้น วิธีนี้เร็ว เขียนโค้ดน้อย และใช้ Realtime ได้
- **เขียน: ทุกอย่างผ่าน Elysia** ทั้งแจ้งเรื่อง อัปโหลดรูป เจอเหมือนกัน ความคิดเห็น แจ้งแก้ รายงาน และงานแอดมิน
  - เหตุผล: ตรรกะสำคัญ (rate limit, กรองคำหยาบ, กันเรื่องซ้ำ, ประมวลผลรูป, ต่อเบลอในอนาคต, บันทึก log) จะอยู่ที่เดียว
  - RLS ปิดการเขียนตรงจากฝั่ง client ทั้งหมด
- **Auth: Supabase Auth** Angular ล็อกอินผ่าน supabase-js แล้วแนบ access token (JWT) ไปกับทุกคำขอเขียน Elysia ตรวจ JWT ด้วย `jose` แบบ JWKS (ES256) ผ่าน `createRemoteJWKSet` จาก `/auth/v1/.well-known/jwks.json` (แก้ในแผน 3 เมื่อ 2026-10-17: ตรวจเครื่องจริงด้วย Supabase CLI 2.121.0 แล้ว access token ของผู้ใช้มี header `{"alg":"ES256","kid":…}` และ JWKS มีคีย์ EC P-256 ส่วน `JWT_SECRET` (HS256) ใช้เซ็นได้แค่ anon key กับ service key แบบเก่า ถ้าตรวจด้วย HS256 token ของผู้ใช้จะไม่ผ่านเลย ข้อดีคือ API ใช้แค่กุญแจสาธารณะ ไม่ต้องถือ secret และ `jose` โหลดคีย์ใหม่เองเมื่อเจอ `kid` ที่ไม่รู้จัก เช่นหลัง `supabase stop/start`) แล้วอ่าน `sub` เป็น user id ถ้าตรวจ `iss` ให้รู้ไว้ว่ามีค่าเป็น `http://127.0.0.1:54321/auth/v1` ไม่ใช่ `/sb`
- **Caddy เป็นจุดเข้าเดียวตั้งแต่วันแรก** ทำให้ไม่มีปัญหา CORS และตอนเปิดให้คนนอกลอง (ขั้นสุดท้าย) แค่ต่อ tunnel เข้าพอร์ต 8000 พอร์ตเดียว ทุกอย่างก็ใช้ได้ทันที
- **พอร์ต:** 8000 (Caddy) และ 54321–54324 (Supabase CLI ค่าเริ่มต้น) ไม่ใช้ 8080 เพราะ `docker-webui` ใช้อยู่ · แผน 6 เพิ่ม **8100** (Caddy site ที่สอง) เสิร์ฟ production build ใน `apps/web/www` พร้อม service worker และส่ง `/api`, `/sb` ต่อเหมือน 8000 (build ด้วย `bash scripts/build-web.sh`)

### 4.4 การทำแผนที่สองโหมด (ภาพประกอบ → ปกติ)

ใช้แผนที่ MapLibre ตัวเดียว ซ้อนเลเยอร์ตามลำดับนี้ (ล่างขึ้นบน):

1. **แผนที่ปกติ** จาก OpenFreeMap
2. **หน้ากากโลก** เป็น polygon คลุมทั้งโลกที่เจาะรูประเทศไทยไว้ ระบายสีทะเล `--sea` ทำให้เห็นแค่ไทย (opacity 1 ที่ zoom ≤ 6 แล้วจางเป็น 0 ที่ zoom 8)
3. **ภาพประกอบ** ตามหัวข้อ 3.2.1:
   - เงาแผ่นดิน 3 ชั้นด้วย `fill-translate` [0, 8/16/24] สีน้ำตาลไล่เข้ม
   - แผ่นดินสีเขียว `#79B83C` ขอบ `#F3E3B0`
   - ภาคอีสานสีส้ม `#F5A04A`
   - เส้นแบ่งจังหวัดบางๆ
   - ป้ายจังหวัด 15 จังหวัด และสัญลักษณ์ Fluent Emoji 3D (symbol layer โดยโหลดภาพทีละไฟล์ด้วย `addImage` แทน sprite sheet) ป้ายจังหวัดทำเป็น HTML marker เพราะตัวเรนเดอร์ glyph ของ MapLibre วางสระและวรรณยุกต์ไทยผิดที่ (แผน 2, 2026-10-17)
   - เมฆ เครื่องบิน และรถไฟ (overlay เคลื่อนไหว)
   - ทุกเลเยอร์ใช้ `*-opacity: ["interpolate", ["linear"], ["zoom"], 6, 1, 8, 0]`
4. **Beacon**:
   - ซูมไกลใช้ GeoJSON source ที่ `cluster: true`, `clusterMaxZoom: 11` และ `clusterProperties` หา max ระดับ
   - ซูมใกล้แสดงลำแสงเป็น **HTML marker** (CSS ตามต้นแบบ) เฉพาะจุดในจอ ไม่เกิน 150 จุด
   - เรื่องที่อยู่เดี่ยวๆ ตอนซูมไกล (ไม่ถูกรวมกลุ่ม) แสดงเป็นลำแสงย่อส่วน (สูง 60 px ไม่มีป้าย) แล้วสูงเต็มตาม `beamHeight` ที่ zoom ≥ 12 (**ตัดสินแล้ว** 2026-10-17)
   - source ของเรื่องต้องมีเลเยอร์ใช้อย่างน้อยหนึ่งชั้น (วงกลมโปร่งใส `reports-anchor`) ไม่อย่างนั้น MapLibre จะไม่โหลดข้อมูลและ `querySourceFeatures` คืนค่าว่าง

ข้อมูลภูมิศาสตร์:

- ขอบเขตประเทศ จังหวัด และอำเภอจาก **OCHA COD-AB ของไทย** (ชุดข้อมูล `cod-ab-tha` บน HDX ไลเซนส์ CC BY-IGO) เพราะมีชื่อภาษาไทย (`ADM1_TH`, `ADM2_TH`) ซึ่ง geoBoundaries ไม่มี ลดความละเอียดด้วย mapshaper แล้วเก็บเป็นไฟล์ใน `supabase/data/` (ใช้สร้างตาราง `admin_areas`) และ `apps/web/src/assets/geo/` (ใช้วาดภาพประกอบ)
- ภาคต่างๆ จับคู่ด้วยตารางจังหวัด → ภาค
- ต้องใส่เครดิตแหล่งข้อมูลในหน้า `/about` และมุมแผนที่ (OSM, OpenFreeMap, OCHA COD-AB)

### 5.2 View สาธารณะ (ให้ Angular อ่าน)

- **`public_reports`**: เรื่องที่ `status in (open, fix_claimed, resolved)` (แผน 6: resolved ทุกอายุ เพื่อให้ `/list` และลิงก์เก่าเปิดได้ ส่วนแผนที่ซ่อนเรื่องที่แก้เกิน 30 วันเองใน `reports_in_bbox`) มีคอลัมน์:
  - `id`, `category`, `danger_level`, `title`, `description`, `status`
  - `lng`/`lat` (จาก `public_location`), `place_name`, `confirm_count`, `comment_count`
  - `days_open`
  - `author_name` (ถ้า `hide_author` จะเป็น null)
  - `cover_photo_url`, `tags[]`, `approved_at`, `resolved_at`

  **ไม่มี** `author_id` และพิกัดจริง
- **`public_comments`**: ความคิดเห็นที่ `visible` ของเรื่องสาธารณะ พร้อม `author_name`
- **`public_stats`**: ฟังก์ชัน `stats_in_bbox(minlng, minlat, maxlng, maxlat)` คืนจำนวนที่แก้แล้วในเดือนนี้และจำนวนที่ค้างอยู่ (แผน 6: "เดือนนี้" นับตามเวลา `Asia/Bangkok`)
- **ฟังก์ชัน `reports_in_bbox(...)`**: คืน GeoJSON FeatureCollection ของเรื่องในกรอบจอ ใช้ป้อนแผนที่ (จำกัด 2000 จุด) เรื่องที่แก้แล้วเกิน 30 วันไม่ขึ้นบนแผนที่ (แผน 6 ย้ายเงื่อนไขนี้มาจาก view)
- **ฟังก์ชัน `list_reports(...)`** (แผน 6): ป้อนหน้า `/list` เรียงได้ 4 แบบ (ใกล้ฉัน ระยะวัดจากจุดสาธารณะ, ใหม่สุด, คนเจอมากสุด, ค้างนานสุด) แบ่งหน้า รับตัวกรองเดียวกับแผนที่ และรวมเรื่องที่แก้แล้วทุกอายุเมื่อขอ
- **ฟังก์ชัน `search_areas(q)`** (แผน 6): ค้นชื่ออำเภอ/จังหวัดไทยและอังกฤษจากตารางในเครื่อง เรียกได้เฉพาะ service role (ผ่าน `GET /api/places`)

### 5.3 RLS

- `anon` และ `authenticated` **SELECT ได้เฉพาะ view/ฟังก์ชันสาธารณะ** กับ `categories`
- ตาราง `reports`: ผู้แจ้ง SELECT เรื่องของตัวเองได้ทุกสถานะ (สำหรับหน้า "ของฉัน")
- ตาราง `profiles`: SELECT/UPDATE แถวของตัวเองได้ แต่แก้ได้แค่ `display_name` กับ `locale` (แผน 4: ชื่อที่แสดงแก้ผ่าน `PATCH /api/me` ซึ่งตรวจความยาวและคำหยาบ ส่วน client ที่เขียนตรงแก้ได้เฉพาะ `locale`)
- **INSERT/UPDATE/DELETE จาก client ปิดทั้งหมด** ทุกการเขียนทำผ่าน API ด้วย service role
- ต้องมีเทสต์ RLS ด้วย pgTAP (`supabase test db`) ว่า anon อ่านเรื่อง `pending_review` ไม่ได้และอ่านพิกัดจริงไม่ได้

### 5.4 Storage

- bucket **`photos-private`** (ไม่สาธารณะ) เป็นที่พักรูปของเรื่องที่ยังไม่ได้อนุมัติ แอดมินดูผ่าน signed URL
- bucket **`photos-public`** (สาธารณะ อ่านอย่างเดียว) เก็บรูปของเรื่องที่อนุมัติแล้ว API ย้ายรูปมาที่นี่ตอนอนุมัติ
- ชื่อไฟล์: `{report_id}/{photo_id}.webp` ใน `photos-public` ส่วนระหว่างรอการอนุมัติรูปอยู่ที่ `photos-private/{uploader_id}/{photo_id}.webp` (กับ `{photo_id}_thumb.webp`) เพราะตอนอัปโหลดยังไม่มี `report_id` ตอนอนุมัติ API ย้ายมาเป็นชื่อแบบแรก
- **ข้อยกเว้น (เจ้าของตัดสินแล้ว, แผน 4):** รูปแรกจากการ "ใช่ กดเจอเหมือนกันแทน" ใน `merge` ถูกแนบเป็นความคิดเห็นและย้ายไป `photos-public` ทันที โดยผู้ดูแลยังไม่ได้ตรวจ และยังไม่มีการเบลอ (ทำในแผน 9) UI ต้องบอกตรงๆ ว่ารูปนี้ขึ้นทันที
- **ไม่เก็บไฟล์ต้นฉบับ** เก็บเฉพาะไฟล์ที่ re-encode แล้วและไม่มี metadata (**ตัดสินแล้วในแชตเดิม**)
- **ไฟล์ย้ายตามการมองเห็น (แผน 5):** ไฟล์อยู่ใน `photos-public` ก็ต่อเมื่อเรื่องสาธารณะ (และความคิดเห็นนั้น `visible`) ซ่อน → ย้ายกลับ `photos-private` ที่พาธเดิม, คืน → ย้ายกลับ `photos-public` ทั้งไฟล์เต็มและ `_thumb` ฐานข้อมูลบอกรายการไฟล์ (`promote`/`demote`) API เป็นผู้ย้าย ล้มเหลวลองอีกครั้งแล้ว log
- **รูปหลังแก้ (แผน 5):** อยู่ `photos-private/{claimant}/{photo}.webp` จนแอดมินยืนยัน แล้วย้ายไป `photos-public/{report}/{photo}.webp`

### 6.1 การล็อกอิน (**ผู้ออกแบบเลือก**)

- **ตอนพัฒนาและเดโม:** ล็อกอินด้วย **อีเมล OTP** (กรอกอีเมลแล้วใส่รหัส 6 หลัก) อีเมลไปตกที่ Mailpit ของ Supabase CLI (`localhost:54324`) จึงไม่ต้องมีบริการส่งเมลจริง
- **Google:** ใส่ไว้ใน config แต่เปิดได้ก็ต่อเมื่อเจ้าของสร้าง OAuth client ใน Google Cloud (ฟรี)
- **LINE กับเบอร์โทร:** เลื่อนไปทีหลัง เพราะ LINE ไม่มีในตัวของ Supabase และ SMS ต้องจ่ายเงิน
- **แอดมิน:** ตั้งด้วยสคริปต์ `scripts/make-admin.sh <email>` ที่ UPDATE `profiles.role`

### 6.2 กติกากันสแปม (**ผู้ออกแบบเลือก**, ค่าอยู่ใน env)

- แจ้งเรื่องได้ 5 เรื่องต่อวันต่อคน, ความคิดเห็น 30 ต่อวัน, แจ้งแก้ 10 ต่อวัน, รายงาน 20 ต่อวัน (นับจาก DB ไม่ต้องมี Redis) โควตาทุกตัวนับ **ย้อนหลัง 24 ชั่วโมง** ไม่ใช่ตามวันปฏิทิน และการอัปโหลดรูปมีโควตาของตัวเองคือ `RATE_LIMIT_PHOTOS_PER_DAY` (ร่วมกับ `RATE_LIMIT_REPORTS_PER_DAY` และตัวอื่นใน env)
- กรองคำหยาบด้วยรายการคำไทยและอังกฤษใน `apps/api/src/moderation/badwords.ts`
  - ความคิดเห็นที่มีคำหยาบถูกปฏิเสธพร้อมข้อความบอก
  - เรื่องที่มีคำหยาบยังรับได้ (เพราะผ่านแอดมินอยู่แล้ว) แต่จะติดธงให้แอดมินเห็น
- เรื่อง**และความคิดเห็น**ที่ถูกรายงานโดยสมาชิก **3 คนที่ต่างกัน** (รายงานที่ยัง `open`) จะถูกซ่อนชั่วคราว (`hidden`) รอแอดมินตัดสิน คนเดียวรายงานซ้ำไม่นับเพิ่ม (แผน 5) ชื่อ env ของโควตาแจ้งแก้และรายงานคือ `RATE_LIMIT_FIX_CLAIMS_PER_DAY` (10) และ `RATE_LIMIT_FLAGS_PER_DAY` (20) หมายเหตุของการแจ้งแก้และการรายงานไม่ผ่านตัวกรองคำหยาบเพราะมีแต่แอดมินที่เห็น

### 6.3 การจัดการรูป

1. **เบราว์เซอร์:**
   - อ่าน EXIF GPS ด้วย `exifr` เพื่อเสนอตำแหน่ง
   - ย่อรูปให้ด้านยาวไม่เกิน 1600 px แล้ว encode เป็น WebP คุณภาพ 0.8 ผ่าน canvas (ขั้นนี้ลบ EXIF ไปด้วย) ถ้าได้ไฟล์ที่ไม่ใช่ WebP กลับมา (Safari/iOS encode WebP จาก canvas ไม่ได้ และจะคืน PNG แทนแบบเงียบๆ) ให้ใช้ JPEG คุณภาพ 0.82 แทน
   - จำกัด 4 รูปต่อเรื่อง และรูปละไม่เกิน 3 MB หลังบีบอัด
2. **API:**
   - ตรวจชนิดไฟล์จาก magic bytes
   - ใช้ `sharp` re-encode เป็น WebP อีกรอบ (ลบ metadata ทุกชนิด) และย่ออีกครั้งถ้าจำเป็น
   - **เรียก `processForPrivacy(image)`** ซึ่งตอนนี้คืนรูปเดิมและตั้ง `blurred=false` (จุดต่อระบบเบลอ ดูหัวข้อ 9)
   - เก็บใน `photos-private/{uploader_id}/{photo_id}.webp` (กับ `{photo_id}_thumb.webp`) เพราะตอนอัปโหลดยังไม่มี `report_id`
3. **ตอนแอดมินอนุมัติ:** ย้ายรูปไป `photos-public` (ซ่อน/คืนย้ายไฟล์ตาม ดู 5.4) **ข้อยกเว้น:** รูปแรกของ `merge` (การ์ดเรื่องซ้ำ "ใช่") ไปที่ `photos-public` ทันทีโดยไม่ผ่านการตรวจ (ดู 5.4) ยังไม่เบลอจนกว่าจะถึงแผน 9
4. **thumbnail:** API สร้างไฟล์ขนาด 400 px ด้วย `sharp` เก็บคู่กันเป็น `{photo_id}_thumb.webp` (**ผู้ออกแบบเลือก**: ไม่ใช้ image transformation ของ Supabase เพราะต้องเปิด imgproxy ที่กินแรมเพิ่ม และต้องเรียกผ่าน endpoint `/render/image/` แยกต่างหาก)

### 6.4 ความเป็นส่วนตัวของพิกัด

- หมวด `hazard` (ความปลอดภัย) ระบบจะเลื่อน `public_location` แบบสุ่มภายใน 150 เมตรโดยอัตโนมัติ (**ผู้ออกแบบเลือก**) แอดมินปิดการเลื่อนหรือตั้งเองได้ตอนอนุมัติ
- **ตำแหน่งตอนอนุมัติ 4 แบบ (แผน 5):** `keep` (ตามเดิม), `exact` (พิกัดจริง = ปิดการเลื่อน), `fuzz` (สุ่มใหม่ ≤ 150 ม.), `point` (แอดมินปักเอง ต้องอยู่ในไทยและห่างจุดจริง ≤ 1,000 ม.; หมุดเริ่มที่จุดที่แสดง ไม่ใช่จุดจริง) ถ้าหมวดสุดท้ายเป็น hazard และจุดที่ได้จาก `keep` หรือ `point` ตรงกับจุดจริงพอดี ระบบเลื่อนให้ มีแต่ `exact` ที่เปิดเผยพิกัดจริงได้ หัวข้ออัตโนมัติและ `place_name` มาจากจุดที่แสดงเสมอ
- หมวดอื่นใช้พิกัดจริง เพราะต้องรู้จุดที่ชัดเจนถึงจะแก้ปัญหาได้

- พอแผนที่หยุดเลื่อน (`moveend`, debounce 300ms) จะเรียก `reports_in_bbox` แล้ว `setData` ให้ GeoJSON source
- ตัวกรอง (ระดับ/หมวด/สถานะ/ข้อความ) ส่งเป็นพารามิเตอร์ของฟังก์ชัน
- ใช้ **Supabase Realtime แบบ Broadcast** บน channel สาธารณะ `reports` ทุกครั้งที่สถานะหรือจำนวน "เจอเหมือนกัน" เปลี่ยน API จะส่งข้อความ `{id, status, confirm_count}` ไป แล้วเว็บโหลดข้อมูลเรื่องนั้นใหม่ (ไม่ใช้ `postgres_changes` เพราะมันผ่าน RLS และ anon อ่านตาราง `reports` ไม่ได้ อีกทั้ง subscribe กับ view ไม่ได้) ลำแสงจึงขึ้นหรือดับทันทีโดยไม่ต้องรีเฟรช ช่วยให้ฉากเดโมขั้น 3 และ 5 ดูดี (**ผู้ออกแบบเลือก**, ถ้าทำไม่ทันใช้รีเฟรชข้อมูลหลังกดแทนได้)

## 8. สภาพแวดล้อมการพัฒนา (Docker ใน WSL)

### 8.1 ติดตั้งครั้งแรก (ใน WSL Ubuntu)

0. **Node ของ Linux ใน WSL** (ทำแล้ว 2026-10-17): Node 22 ที่ `~/.local/node` ห้ามใช้ Node ของ Windows ที่ WSL เรียกข้ามมา `scripts/check-tools.sh` ตรวจจุดนี้ให้
1. Docker Compose plugin (ทำแล้ว 2026-10-17: ติดตั้ง Compose v5 แบบผู้ใช้ที่ `~/.docker/cli-plugins` เพราะ sudo ต้องใช้รหัสผ่าน วิธีเดิมใช้แทนได้): ดูก่อนด้วย `dpkg -l | grep -E 'docker|containerd'` ว่า Docker มาจากแพ็กเกจไหน ถ้าเป็น `docker.io` ของ Ubuntu ให้ติดตั้ง `docker-compose-v2` ถ้าเป็น `docker-ce` ของ Docker ให้ติดตั้ง `docker-compose-plugin` อย่าผสมสองแบบ
2. Supabase CLI: ใช้ผ่าน `npx supabase` โดยใส่ไว้เป็น devDependency ที่ `package.json` ระดับราก ไม่ติดตั้ง global
3. Bun: ไม่จำเป็นต้องมีบนเครื่อง เพราะ API รันใน image `oven/bun` แต่ติดตั้งไว้ใช้คำสั่ง `bun` ตรงๆ ได้ถ้าต้องการ
4. `supabase init` แล้วแก้ `supabase/config.toml`:
   - ปิด `analytics` และ `edge_runtime` เพื่อประหยัดแรม (ทั้งระบบควรอยู่ราว 3–4 GB จากที่มี 7.7 GB)
   - OTP 6 หลัก: แก้เทมเพลตอีเมลทั้ง **magic link** และ **confirmation** (ผู้ใช้ใหม่จะได้ฉบับ confirmation) ให้มี `{{ .Token }}` ผ่าน `[auth.email.template.*]` และตั้ง `auth.email.otp_length = 6`
   - เพิ่ม `auth.rate_limit.email_sent` ให้สูงพอสำหรับการซ้อมเดโม
   - ตั้ง `site_url = "http://localhost:8000"`

### 8.2 รันทุกวัน

```bash

./scripts/dev-down.sh  # docker compose down → supabase stop
```

- แอป: http://localhost:8000
- Supabase Studio (ดู/แก้ DB): http://localhost:54323
- Mailpit (ดูอีเมล OTP): http://localhost:54324

`docker-compose.yml`:

- **caddy**: image `caddy:2` เปิดพอร์ต 8000
- **web**: image `node:22` รัน `ng serve --host 0.0.0.0 --poll 1000`, bind mount `apps/web` และใช้ volume แยกเก็บ `node_modules` ต้องตั้ง `allowedHosts` ของ dev server ให้รับ Host ที่มาผ่าน Caddy (และ IP ใน LAN)
- **api**: image `oven/bun` รัน `nodemon -L --watch src --exec "bun src/index.ts"` (`bun --watch` ไม่มีโหมด polling จึงไม่เห็นไฟล์ที่เปลี่ยนบน `/mnt/d`), bind mount `apps/api`
- Caddy ใช้ `handle_path /sb/*` และ `handle_path /api/*` เพื่อตัด prefix ก่อนส่งต่อ (API ฝั่ง Elysia จึงรับ path แบบไม่มี `/api`)
- **โหมดเดโม** (`scripts/demo-up.sh`): build web แบบ production แล้วให้ Caddy เสิร์ฟไฟล์ static แทน `ng serve` เพื่อให้ PWA และ service worker ทำงาน และให้โหลดเร็ว (แผน 6 ทำส่วนแรกแล้ว: `scripts/build-web.sh` build ลง `apps/web/www` และ Caddy เสิร์ฟที่พอร์ต 8100 คู่กับ dev server ที่ 8000)
- ทุก service ต่อเข้า external network `supabase_network_Jaeng` (ชื่อจริงดูจาก `docker network ls` หลัง `supabase start`) เพื่อเรียก Kong ที่ `supabase_kong_Jaeng:8000`

**เรื่องโฟลเดอร์บนไดรฟ์ D:** (**ผู้ออกแบบเลือก**) เก็บโค้ดไว้ที่ `D:\Project\Jaeng` ตามเดิม แต่ไฟล์บน `/mnt/d` ถูก Docker ใน WSL อ่านช้าและไม่ส่งสัญญาณไฟล์เปลี่ยน จึงต้องใช้ `--poll` (กับ `bun --watch` ก็อาจต้องตั้ง polling ด้วย) ถ้าช้าจนรำคาญ ให้ย้ายโปรเจ็กต์ไปไว้ที่ `~/jaeng` ใน WSL แล้วเปิดจาก Windows ผ่าน `\\wsl$\Ubuntu\home\...` จะเร็วขึ้นมาก

### 8.4 แอป Android (APK)

(**ตัดสินแล้ว**: ใช้มือถือจริง ติดตั้งด้วย APK)

**Build ใน Docker** (ไม่ต้องติดตั้ง Android Studio): ใช้ `infra/android/Dockerfile` ที่มี JDK 21, Android command-line tools, platform และ build-tools ที่ Capacitor ต้องการ แล้วรัน `scripts/build-apk.sh <ที่อยู่เซิร์ฟเวอร์>` สคริปต์นี้ทำ 3 อย่าง:

1. `ng build` (production)
2. `npx cap sync android`
3. `./gradlew assembleDebug` ภายในคอนเทนเนอร์

ผลลัพธ์อยู่ที่ `dist/jaeng-debug.apk` ใช้ debug key ซึ่งพอสำหรับติดตั้งเอง (**ผู้ออกแบบเลือก**) ส่งไฟล์ไปมือถือแล้วกดติดตั้ง (ต้องเปิด "ติดตั้งแอปที่ไม่รู้จัก") หรือใช้ `adb install` ผ่าน Wi-Fi debugging

**การเชื่อมต่อมือถือกับคอม:**

- มือถือกับคอมต้องอยู่ Wi-Fi วงเดียวกัน แล้วแอปเรียก `http://<IP ของคอม>:8000` ซึ่งเป็น Caddy จุดเดียวกับเว็บ
- (**แก้ 2026-10-21 ตามแผน 7**) ไม่ใช้ mirrored networking: ลองแล้วทำให้ `127.0.0.1` ใน WSL ใช้ไม่ได้ และ Supabase CLI พัง ทางเข้าสำหรับมือถือคือ **Cloudflare quick tunnel** (`scripts/tunnel.sh`, https สาธารณะ, ไม่ต้องแก้ firewall, ข้อมูลตัวอย่างเท่านั้นตามหัวข้อ 9.2) ที่อยู่เปลี่ยนทุกครั้งที่เปิด จึงตั้งในแอปได้ ส่วนการเปิดพอร์ต 8000 ออก LAN เองยังทำได้ถ้าต้องการ
- ใน Capacitor config ตั้ง `server.androidScheme = "http"` และอนุญาต cleartext (`android:usesCleartextTraffic`) เพราะเซิร์ฟเวอร์ใน LAN เป็น http
- IP ของคอมเปลี่ยนได้ แอปจึงมีหน้า **ตั้งค่าเซิร์ฟเวอร์** (ใน `/me` และขึ้นเองถ้าเชื่อมต่อไม่ได้) ให้แก้ที่อยู่แล้วกด "ทดสอบ" ซึ่งเรียก `/api/health`
- Supabase Auth: ตั้ง `additional_redirect_urls` ให้รวม IP ใน LAN การล็อกอินใช้ OTP 6 หลัก จึงไม่ต้องทำ deep link กลับเข้าแอป
- GPS ใน APK ใช้ `@capacitor/geolocation` ซึ่งขอสิทธิ์แบบ native ไม่ติดเงื่อนไข secure context ของเบราว์เซอร์
- กล้องใน APK ใช้ `@capacitor/camera` และยังเลือกจากคลังได้

**ไอคอนแอปและ splash:** ใช้โลโก้ "แจ้ง" (ลำแสงบนวงกลม โทน pastel) สร้างด้วย `@capacitor/assets`

### 8.5 ข้อมูลตัวอย่าง (seed)

`supabase/seed.sql` สร้างข้อมูลสำหรับเดโม:

- ผู้ใช้ตัวอย่าง 5 คน (1 แอดมิน) มีรหัสผ่านไว้ให้ **ปุ่มสลับผู้ใช้สำหรับเดโม** (**ผู้ออกแบบเลือก**) ปุ่มนี้แสดงเฉพาะเมื่อ `DEV_QUICK_LOGIN=true` และเปิดที่ `localhost` เท่านั้น กดแล้วล็อกอินเป็นผู้แจ้ง/แอดมิน/ผู้ใช้คนที่สองได้ทันที ส่วนการล็อกอินด้วย OTP จริงยังโชว์ได้หนึ่งรอบ
- เรื่อง **ราว 40 เรื่องกระจายทั่วประเทศ** (รวม 13 เรื่องจากต้นแบบ) ครบทุกระดับและทุกสถานะ
- ความคิดเห็นและ "เจอเหมือนกัน"
- รูปตัวอย่างเป็นภาพ CC0/public domain จาก Wikimedia Commons หรือ Openverse (**ผู้ออกแบบเลือก**) เลือกภาพที่ไม่มีใบหน้าหรือป้ายทะเบียนชัดเจน เก็บใน `supabase/seed-photos/` พร้อมไฟล์ `CREDITS.md` เจ้าของเปลี่ยนเป็นรูปที่ถ่ายเองได้

`seed.sql` อัปโหลดไฟล์ขึ้น Storage ไม่ได้ จึงต้องมีสคริปต์ `scripts/seed.ts` (รันด้วย bun) เพื่ออัปโหลดรูปและสร้างผู้ใช้ผ่าน Admin API แล้วผูกรูปเข้ากับเรื่อง `scripts/reset-db.sh` จะรัน `npx supabase db reset` ต่อด้วยสคริปต์นี้ ใช้แค่ตอนพัฒนาและเดโมเท่านั้น ข้อมูลจริงเจ้าของเติมเองทีหลัง (**ตัดสินแล้ว**)

## 9. งานที่เลื่อนไปทำทีหลัง

### 9.1 เบลอใบหน้าและป้ายทะเบียน (ทำก่อนเปิดให้คนนอก)

- จุดต่อมีอยู่แล้ว: ฟังก์ชัน `processForPrivacy()` ใน API กับคอลัมน์ `report_photos.blurred`
- แนวทางจากแชตเดิม:
  - ใบหน้าใช้ **YuNet** (OpenCV) ซึ่งรันได้ในคอนเทนเนอร์ Python เล็กๆ ที่ API เรียกผ่าน HTTP
  - ป้ายทะเบียนไทยต้องทดสอบก่อน ถ้าโมเดลสำเร็จรูปพลาดก็ fine-tune YOLO เอง ซึ่งเป็นจุดโชว์ฝีมือ ML ได้
- เมื่อทำเสร็จ หน้าแอดมินจะแสดงป้าย "เบลอแล้ว" และปุ่มเบลอเพิ่มด้วยมือ
- **จนกว่าจะทำเสร็จ:** ข้อความ "เบลอใบหน้าและป้ายทะเบียนแล้ว" ในต้นแบบห้ามแสดง และห้ามเปิดให้คนนอกเข้าถึง

### 9.2 เปิดให้คนอื่นลอง (ขั้นสุดท้าย)

- ใช้ **Cloudflare Quick Tunnel**: `cloudflared tunnel --url http://localhost:8000`
  - ไม่ต้องมีบัญชี ได้ HTTPS ฟรี
  - URL สุ่มใหม่ทุกครั้งที่รัน ต้องเอา URL ไปใส่ `site_url` และ `additional_redirect_urls` ของ Supabase Auth ทุกรอบ ควรทำสคริปต์ช่วย
- เพราะทุกอย่างอยู่หลัง Caddy พอร์ตเดียว จึงต่อ tunnel ได้ทันทีโดยไม่ต้องแก้โค้ด
- ทางเลือก: ngrok (ตรวจหน้าราคาแผนฟรีก่อน), Tailscale Funnel
- เช็กลิสต์ก่อนเปิด:
  - เบลอเสร็จแล้ว
  - เปลี่ยนรหัสผ่านและคีย์ตัวอย่างทั้งหมด
  - ปิด Studio และ Mailpit ไม่ให้ออกไปข้างนอก (tunnel ชี้แค่พอร์ต 8000)
  - เปิดอีเมลจริงสำหรับ OTP (เช่น SMTP ของ Gmail) หรือเปิด Google login

## 13. คำถามที่ยังเปิดอยู่

ตอบแล้ว (2026-10-16): ทำครบทุกเฟสไม่จำกัดเวลา, ใช้มือถือ Android จริงผ่าน APK และวันเดโมมีอินเทอร์เน็ต

ยังเปิดอยู่ (ไม่ขวางการเริ่มงาน):

1. **ล็อกอินด้วย Google** ต้องใช้ไหม (ต้องสร้าง OAuth client เอง และใน APK ต้องทำ deep link เพิ่ม) ถ้าไม่ต้องใช้ ก็ใช้อีเมล OTP อย่างเดียว ซึ่งเป็นค่าเริ่มต้น
2. **ย้ายโฟลเดอร์เข้า WSL** ไหม ตอนนี้ออกแบบให้อยู่ที่ D: ตามเดิม

## 14. สิ่งที่ปล่อยให้ผู้สร้างตัดสินใจเอง

- ชุดไอคอน SVG ของหมวดที่ใช้ใน UI (ต้องไลเซนส์เปิดและเข้ากับโทน pastel)
- ตำแหน่งที่แน่นอนของสัญลักษณ์แต่ละชิ้นบนภาพประกอบ และเส้นทางของเมฆ เครื่องบิน และเรือ
- รายละเอียดแอนิเมชัน (ความเร็ว flyTo, easing)
- รายการคำหยาบเริ่มต้น
- โครงสร้างไฟล์ย่อยภายใน `apps/web` และ `apps/api`
