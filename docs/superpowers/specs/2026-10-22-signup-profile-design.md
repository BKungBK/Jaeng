# แจ้ง: สมัครด้วยอีเมลจริง (Resend) และตั้งชื่อเล่น + รูปโปรไฟล์ตอนสมัคร

วันที่ 22 ต.ค. 2026 · สถานะ: **อนุมัติและทำแล้ว** (ดู `docs/superpowers/plans/2026-10-22-09-signup-profile.md`; ที่ต่างจากเอกสาร: ไฟล์รูปรับไม่เกิน 3 MB เท่ากับรูปแจ้งเรื่อง, เกินโควตาใช้รหัส `rate_limited` เดิม, ฟังก์ชันของผู้ดูแลอยู่ใน migration เดียวกับตารางโปรไฟล์, ป้าย "ชื่อที่แสดง" ในหน้า "ของฉัน" เปลี่ยนเป็น "ชื่อเล่น") · ต่อจาก `2026-10-16-jaeng-design.md` (หัวข้อ 3.1 ล็อกอิน, 5.1 `profiles`, 6 ความปลอดภัย)

## 1. เจตนา

ตอนนี้ล็อกอินเป็นรหัส OTP 6 หลักทางอีเมลที่ส่งเข้า Mailpit บนเครื่องเรา ผู้ใช้จริงจึงยังไม่ได้รับอีเมล และคนที่สมัครใหม่ได้ชื่อสุ่ม "เพื่อนบ้าน0000" โดยไม่ได้เลือก เป้าหมายคือให้คนทั่วไปสมัครและเข้าใช้ได้จริง: อีเมลถึงกล่องจดหมายของเขา แล้วเขาตั้งชื่อเล่นและรูปของตัวเองตั้งแต่ครั้งแรก

สำเร็จเมื่อ: คนที่ไม่เคยใช้แจ้งใส่อีเมล ได้รหัสในกล่องจดหมายจริง ใส่รหัส แล้วต้องตั้งชื่อเล่น (รูปไม่บังคับ) ก่อนเข้าใช้ และชื่อกับรูปนั้นขึ้นที่ที่คนอื่นเห็นชื่อเขา (ตามกติกาปิดชื่อเดิม)

## 2. ที่เจ้าของตัดสินแล้ว

- ส่งรหัสผ่าน **Resend** ด้วยโดเมน `bkungbk.online` (DKIM และ SPF ขึ้น verified แล้ว ภูมิภาค ap-northeast-1)
- **ชื่อเล่น = ชื่อที่แสดง** ช่องเดียว (`profiles.display_name`) ไม่มีชื่อที่แสดงแยก
- โปรไฟล์ตอนสมัครมี **ชื่อเล่น + รูปโปรไฟล์**
- ผู้ใช้ใหม่ตั้งชื่อ **หลังใส่รหัสถูก ข้ามไม่ได้**
- ระบบจริงรันจากสแตกในรีโปนี้ (Supabase CLI + docker) จึงตั้ง SMTP ใน `supabase/config.toml`
- หน้าตาต้องเหมือนระบบเดิม ใช้ชิ้นส่วนที่มีอยู่ ไม่สร้างสไตล์ใหม่

## 3. ที่ผมเลือกเอง (ขอให้ตรวจ)

1. **รูปไม่บังคับ** ชื่อบังคับ (เจ้าของบอกว่าข้ามชื่อไม่ได้ ไม่ได้พูดถึงรูป) ไม่เลือกรูปก็กด "เริ่มใช้แจ้ง" ได้ ไม่มีปุ่มข้ามแยก
2. ช่องชื่อ **ว่างตอนเริ่ม** ไม่เติมชื่อสุ่มให้ เพื่อไม่ให้กดผ่านด้วยชื่อ "เพื่อนบ้าน0000"
3. ชื่อไม่ต้องไม่ซ้ำกัน (เหมือนเดิมวันนี้)
4. รูปถูกตัดเป็นสี่เหลี่ยมจัตุรัสกลางภาพที่ฝั่งเซิร์ฟเวอร์ ย่อเหลือ 256 px เป็น WebP ไม่มีหน้าจอให้ครอปเอง
5. รูปโปรไฟล์ **ไม่ผ่านการเบลอใบหน้า/ป้ายทะเบียน** ของรูปแจ้งเรื่อง (เป็นหน้าตัวเองที่เลือกเอง) แต่ลบ EXIF/GPS เหมือนกัน
6. คนที่มีบัญชีอยู่แล้ว (รวมผู้ใช้เดโมและแอดมินในข้อมูลตัวอย่าง) **ไม่ต้องผ่านขั้นนี้** ถือว่าตั้งแล้ว
7. SMTP ของ Resend เปิดเป็นค่าเริ่มต้น และมีสคริปต์สลับกลับไปใช้ Mailpit ตอนพัฒนา (หัวข้อ 4)

## 4. ส่วนที่ 1: อีเมลผ่าน Resend

- `supabase/config.toml`: เปิด `[auth.email.smtp]` ชี้ `smtp.resend.com` พอร์ต 465 ผู้ใช้ `resend` รหัสผ่านคือ API key อ่านจาก `env(RESEND_API_KEY)` ผู้ส่ง `noreply@bkungbk.online` ชื่อผู้ส่ง "แจ้ง"
- **คีย์เก็บใน `supabase/.env`** (ไฟล์นี้อยู่ใน `.gitignore` อยู่แล้ว ผ่าน `.env`) ไม่ใช้ `.env` ที่ราก เพราะ `scripts/gen-env.sh` เขียนทับทุกครั้ง และไม่ให้เจ้าของวางคีย์ในแชต
- เทมเพลตอีเมลมีอยู่แล้ว (`supabase/templates/confirmation.html` สำหรับคนใหม่, `magic_link.html` สำหรับคนเก่า) ใช้ต่อ ตรวจว่าแสดงชื่อผู้ส่งและตัวรหัสถูกต้อง
- `scripts/mail-mode.sh resend|mailpit` สลับบรรทัด `enabled` ของบล็อก SMTP แล้วบอกให้รีสตาร์ต Auth; `dev-up.sh` เตือนถ้าเปิด Resend แต่ยังไม่มีคีย์
- ขีดจำกัด: Resend แผนฟรีส่งได้ประมาณ 100 ฉบับต่อวัน (ตรวจตัวเลขจริงตอนทำแผน) และ `auth.rate_limit.email_sent` ใน config เป็น 100 ต่อชั่วโมง ใส่ไว้ในข้อความเตือนของ README
- **งานของเจ้าของ (ไม่ใช่โค้ด):** สร้าง API key ใน Resend (สิทธิ์ Sending access เฉพาะโดเมนนี้) ใส่ใน `supabase/.env` บรรทัด `RESEND_API_KEY=...` และเพิ่ม DMARC (`_dmarc` ตอนนี้ `not_started`) ที่ผู้ให้บริการ DNS ไม่มีผลกับการส่งแต่ช่วยให้อีเมลไม่ตกกล่องสแปม
- ไม่ทำ: เปลี่ยนวิธีล็อกอิน (ยัง OTP ล้วน ไม่มีรหัสผ่าน ไม่มี Google)

## 5. ส่วนที่ 2: ขั้น "ตั้งโปรไฟล์"

### เส้นทาง

```
ใส่อีเมล → ใส่รหัส 6 หลัก → (ผู้ใช้ใหม่) ตั้งโปรไฟล์ → เข้าใช้
                          └ (ผู้ใช้เดิม) เข้าใช้เลย
```

- รู้ว่าใครเป็นผู้ใช้ใหม่จาก `profiles.onboarded_at is null`
- ขั้นนี้อยู่ใน **ฟอร์มล็อกอินเดิม** (`LoginFormComponent` เพิ่มขั้นที่สาม `'profile'` ต่อจาก `'email'`, `'code'`) จึงได้ทั้งแผ่นล่างบนมือถือ การ์ดกลาง และหน้า `/login` ฟรี
- ปิดแผ่นกลางทางหรือเข้าด้วยทางลัด (เดโม) ไม่ทำให้ข้ามได้: เมื่อมีเซสชันแต่ `onboarded_at` ยังว่าง ระบบเปิดแผ่นตั้งโปรไฟล์ซ้ำ (`ProfileSetupService` เหมือน `LoginPromptService`) แผ่นนี้ไม่มีปุ่มปิด มีแค่ลิงก์ "ออกจากระบบ"
- ผู้ใช้เดโมที่เข้าด้วยปุ่มลัดเป็นผู้ใช้เดิมอยู่แล้ว จึงไม่เจอขั้นนี้

### หน้าตา (ใช้ชิ้นส่วนเดิมทั้งหมด)

ในกรอบเดียวกับขั้นอีเมลและขั้นรหัส ใช้ class และตัวอักษรเดิมของ `login-form` ตามลำดับบนลงล่าง:

1. `h2.head` "ตั้งโปรไฟล์ของคุณ" (คำใหม่ใน `th.ts`/`en.ts` เท่านั้น)
2. `p.lede` บอกสั้นๆ ว่าชื่อนี้คือชื่อที่คนอื่นเห็นข้างเรื่องที่แจ้งและความคิดเห็น (เว้นแต่เลือกปิดชื่อ) ใช้ประโยคจริงเดียวกับ `me.nameNote` ถ้าความหมายตรง
3. **วงรูป** 80 px ตรงกลาง: หน้าตาเดียวกับ `.face` ของปุ่มบัญชี (วงกลม ผิวสีอ่อนของ accent 24%) ถ้ายังไม่มีรูปแสดงอักษรตัวแรกของชื่อที่กำลังพิมพ์ด้วย `initialOf()` (ฟังก์ชันเดียวกับปุ่มบัญชี) ถ้ามีรูปแสดงรูปในวงเดียวกัน
4. ปุ่มสองปุ่มแบบ `photo-step`: `btn big` ไอคอน `camera` "ถ่ายรูป" (คำ `fixForm.camera`) และ `btn big` ไอคอน `image` "เลือกจากคลัง" (`fixForm.gallery`) ที่ซ่อน `<input type=file>` เหมือนกัน เมื่อมีรูปแล้วเพิ่มปุ่มวงกลม `ctl` ไอคอน `x` ที่มุมวงรูปเพื่อเอาออก (เหมือนปุ่ม `remove` ของ `photo-step`)
5. `label.field` "ชื่อเล่น" + `input.input` `autocomplete="nickname"` นับตัวอักษร `n/30` และบรรทัดคำใบ้ `me.nameHint` เหมือนช่องชื่อในหน้า "ของฉัน" ข้อผิดพลาดใช้ `p.error` ใต้ช่อง (คำหยาบ `profanity`, ความยาว `invalid_display_name`) ผ่าน `i18n.say()`
6. `button.primary` (dawn) "เริ่มใช้แจ้ง" กดไม่ได้จนกว่าชื่อจะถูกกติกา (2–30 ตัวอักษร) ขณะส่งขึ้น "กำลังบันทึก…" เหมือน `load.saving`
ไม่มีปุ่ม "ข้ามรูป" แยก: รูปไม่บังคับ แค่ไม่เลือกรูปก็กดปุ่มข้อ 6 ได้

อนิเมชันใช้ชุดเดิม: ขั้นเปลี่ยนด้วย `rise`, รูปที่อัปโหลดสำเร็จมีเครื่องหมายถูก `app-tick`, ปุ่มที่ส่งอยู่มี `sheen`, ชื่อผิดสั่น 4px สองครั้ง ตรวจที่ 375 px ทั้งสองธีมและสองภาษา

### กติกาชื่อ

ใช้ `checkName` เดิมทุกอย่าง (2–30 ตัวอักษรนับ code point, ไม่มีอักขระควบคุม/ล่องหน, กรองคำหยาบ) ไม่เพิ่มกติกาใหม่

## 6. ส่วนที่ 3: รูปโปรไฟล์

### ที่เก็บและการประมวลผล

- ที่เก็บใหม่ `avatars` เป็น bucket **สาธารณะ** (ใครก็เห็นรูปได้ผ่านที่อยู่ตรง เหมือน `photos-public`) จำกัด 1 MB รับ `image/webp`
- ไฟล์อยู่ที่ `avatars/{user_id}/{uuid}.webp` ใช้ชื่อใหม่ทุกครั้งที่เปลี่ยน เพื่อไม่ให้แคชเก่าค้าง แล้วลบไฟล์เก่า `profiles.avatar_path` เก็บเส้นทางล่าสุด
- API ใหม่ `PUT /me/avatar` (multipart ช่อง `file`, ต้องเป็นสมาชิกและไม่ถูกแบน) ตรวจ magic bytes (`sniffImage`), ถอดรหัสและตัดกลางเป็น 256×256 WebP ด้วย sharp (ไม่ส่งต่อ metadata) จำกัดอัตราด้วยตัวนับใหม่ `RATE_LIMIT_AVATARS_PER_DAY` (ค่าเริ่มต้น 10) และ `DELETE /me/avatar` สำหรับเอาออก
- `PATCH /me` รับ `complete_profile: true` พร้อม `display_name` เพื่อบันทึกชื่อและตั้ง `onboarded_at = now()` ในครั้งเดียว (ผู้ใช้ที่ส่งรูปแล้วแต่ยังไม่กดเริ่ม ยังถือว่าไม่ผ่านขั้นนี้)

### ที่ที่รูปแสดง

| ที่ | หน้าตา |
|---|---|
| ปุ่มบัญชี (แถบค้นหา และแท็บ "ของฉัน" บนมือถือ) | รูปแทนอักษรตัวแรกในวง `.face` เดิม |
| เมนูบัญชี | วง 32 px หน้าชื่อ |
| หน้า "ของฉัน" | วง 72 px ข้างชื่อ มีปุ่ม "เปลี่ยนรูป" และ "เอารูปออก" ในแถวชื่อเดิม (รูปแบบเดียวกับปุ่ม `me.edit`) |
| บรรทัดผู้แจ้งในแผงรายละเอียดและชื่อผู้คอมเมนต์ | วง 24 px หน้าชื่อ **แสดงเฉพาะเมื่อแสดงชื่อ** ถ้าผู้แจ้งปิดชื่อ ทั้งชื่อและรูปไม่แสดง |
| หน้าผู้ดูแล (คนแจ้ง, ผู้ใช้) | วง 32 px หน้าชื่อ |

วงรูปทุกขนาดเป็นคอมโพเนนต์เดียว `AvatarComponent` (รับ `name`, `path`, `size`) แสดงรูปถ้ามี ไม่มีก็แสดงอักษรตัวแรก จึงไม่มีสองหน้าตา

### ความปลอดภัยและการดูแล

- รูปที่อัปโหลดเป็นเนื้อหาสาธารณะ ผู้ดูแลต้องเอาออกได้: ปุ่ม "เอารูปออก" ในแถวผู้ใช้ของหน้าผู้ดูแล (`POST /admin/users/:id/remove-avatar`) บันทึกลงบันทึกผู้ดูแล (เพิ่มค่า `remove_avatar` ใน `LOG_ACTIONS` และข้อความไทย/อังกฤษ) ผู้ใช้ที่ถูกแบนอัปโหลดใหม่ไม่ได้
- ผู้ใช้เปลี่ยน/เอารูปได้ตลอดจากหน้า "ของฉัน" ชื่อก็แก้ได้เหมือนเดิม
- ไม่ทำภาพคล้ายหน้าบุคคลสาธารณะ ไม่มีการกรองเนื้อหารูปอัตโนมัติ (ทำเหมือนรูปแจ้งเรื่อง: มีคนดูแลตรวจย้อนหลัง)

## 7. ข้อมูล (migration ใหม่ 1 ไฟล์)

- `profiles.avatar_path text` และ `profiles.onboarded_at timestamptz`; แถวที่มีอยู่ตอน migrate ตั้ง `onboarded_at = created_at`
- `handle_new_user` คงชื่อสุ่มไว้เป็นค่าชั่วคราวจนกว่าจะตั้งโปรไฟล์ (ผู้ใช้ไม่เห็นชื่อนี้ในแผ่นตั้งโปรไฟล์)
- `profiles`: ผู้ใช้เขียนตรงได้เท่าเดิม (`locale`) การแก้ `avatar_path`/`onboarded_at` ผ่าน API ด้วย service role เท่านั้น
- มุมมอง `public_reports` และ `public_comments` เพิ่มคอลัมน์ `author_avatar` (เป็น `null` เมื่อปิดชื่อ ใช้เงื่อนไขเดียวกับ `author_name`) และฟังก์ชันของผู้ดูแลที่ส่ง `Person` เพิ่ม `avatar_path`
- `scripts/seed.ts` ตั้ง `onboarded_at` ให้ผู้ใช้ตัวอย่างทั้งหมด; `bash scripts/gen-types.sh` สร้าง `database.types.ts` ใหม่
- pgTAP: คอลัมน์ใหม่, ผู้ใช้เขียน `avatar_path`/`onboarded_at` ตรงไม่ได้, มุมมองซ่อนรูปเมื่อปิดชื่อ, bucket `avatars` เขียนได้เฉพาะ service role

## 8. สิ่งที่ไม่ทำ

ล็อกอินด้วยรหัสผ่าน/Google/โซเชียล · ชื่อไม่ซ้ำ · คำแนะนำตัว (bio) · หน้าครอปรูป · กรองรูปด้วย AI · หน้าโปรไฟล์สาธารณะของผู้ใช้อื่น · ส่งอีเมลอื่นนอกจากรหัส (เช่นแจ้งสถานะเรื่อง)

## 9. การทดสอบ
