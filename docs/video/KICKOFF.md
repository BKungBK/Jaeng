# เริ่มทำคลิปนำเสนอ "แจ้ง": prompt เริ่มงานและชุดคำถามที่ AI ต้องถามก่อนลงมือ

## วิธีใช้ (สำหรับผู้ใช้)

1. เปิดแชตใหม่ในโฟลเดอร์ `D:\Project\Jaeng` (รันบน Windows ไม่ใช่ใน WSL)
2. เลือกโมเดลตามเซสชันที่จะทำ (ข้อเสนอ ยังไม่ได้วัดการใช้โควตา): เซสชัน 1 และ 3 ใช้ Opus 5.5 effort high เซสชัน 2 ใช้ Sonnet 5.5 effort high
3. วางข้อความในกรอบ "PROMPT เริ่มงาน" ด้านล่างทั้งหมด
4. ตอบคำถามที่ AI ถามให้ครบ (ถามเป็นชุดละไม่เกิน 4 ข้อ มีคำตอบแนะนำเป็นข้อแรกเสมอ) ถ้าข้อไหนไม่แน่ใจ เลือกข้อแนะนำได้ คำตอบทั้งหมดถูกบันทึกใน `video/ANSWERS.md` (ไฟล์นี้ git ไม่ติดตาม เพราะมีอีเมล) ครั้งต่อไปไม่ต้องตอบซ้ำ

---

## PROMPT เริ่มงาน (คัดลอกตั้งแต่บรรทัดถัดไปถึงก่อนเส้นคั่น)

อ่าน `docs/video/KICKOFF.md` ส่วน "คำสั่งสำหรับ AI" แล้วทำตามทุกข้อ นี่คือการเริ่มงานทำคลิปนำเสนอโปรเจกต์ "แจ้ง" รายละเอียดการผลิตทั้งหมดอยู่ใน `docs/video/PROMPT-motion-clip.md` (prompt หลัก) สคริปต์พูดอยู่ใน `docs/video/script-th.md` และแผนผังอยู่ใน `docs/video/diagram-system.svg` ก่อนทำอะไรที่เปลี่ยนสถานะเครื่องหรือระบบ (build, ส่งอีเมล, ติดตั้ง, เปิดหรือปิดสแตก, สร้างเสียง, เรนเดอร์) ให้ตรวจสถานะแบบอ่านอย่างเดียวก่อน แล้ว **ถามผมให้ครบทุกข้อที่ยังไม่มีคำตอบ** ด้วยเครื่องมือถามคำถาม (ชุดละไม่เกิน 4 ข้อ มีตัวเลือกแนะนำเป็นข้อแรก) บันทึกคำตอบลง `video/ANSWERS.md` สรุปแผนสั้น ๆ แล้วรอผมยืนยันก่อนเริ่มลงมือ ตอบผมเป็นภาษาไทย สั้น กระชับ

## คำสั่งสำหรับ AI

### ขั้น 0: ห้ามเริ่มสร้างอะไรก่อนทำขั้น 1 ถึง 4 ให้ครบ

คุณจะถามผมก่อน เพราะงานนี้ใช้ทรัพยากรและโควตามาก การเดาผิดแล้วทำซ้ำเสียทั้งเวลาและโควตา ข้อห้าม: ห้ามส่งอีเมล, ห้าม build APK, ห้ามเปิดหรือปิดสแตก, ห้ามติดตั้งแพ็กเกจ, ห้ามเรียก ElevenLabs, ห้ามเรนเดอร์ จนกว่าผมจะยืนยันแผนในขั้น 4

### ขั้น 1: ตรวจสถานะ (อ่านอย่างเดียว ผลลงไฟล์ ดูเฉพาะสรุป)

ตรวจและจำผลไว้ใช้ในขั้น 2 (ไม่ต้องถามผมเรื่องที่ตรวจเองได้):
1. มี `video/STATE.md` ไหม ถ้ามี อ่านแล้วบอกว่าเซสชันก่อนหน้าทำถึงไหน (ถ้ามี `video/ANSWERS.md` ให้อ่านและข้ามคำถามที่ตอบแล้ว)
2. มีไฟล์เสียงใน `video/audio/raw/` ไหม กี่ไฟล์ ชื่ออะไร ความยาวรวม
3. สแตกรันอยู่ไหม (`http://localhost:8000/api/health`), สถานะโหมดอีเมล (`bash scripts/mail-mode.sh status`)
4. มือถือเชื่อมไหม (`adb devices -l`, `adb reverse --list`) พาธเต็มของ adb และ scrcpy อยู่ที่ `%LOCALAPPDATA%\Microsoft\WinGet\Packages\Genymobile.scrcpy_Microsoft.Winget.Source_8wekyb3d8bbwe\scrcpy-win64-v4.1\`
5. เครื่อง: RAM ว่าง, VRAM, พื้นที่ดิสก์ D:, `ffmpeg -encoders` มี `h264_nvenc` ไหม, Node, Python, มี Chrome ไหม
6. โค้ดแอปเปลี่ยนหลัง APK ล่าสุด (`dist/jaeng-debug.apk`) หรือหลังการรันเทสต์ล่าสุด (2026-10-22) ไหม (`git log` ตั้งแต่ 2026-10-22 14:30, `git status`) ถ้าเปลี่ยน ต้องรันเทสต์และสร้าง APK ใหม่ และตัวเลขในสคริปต์หัวข้อ 9 อาจเก่า
7. `docs/video/script-th.md` และ `PROMPT-motion-clip.md` ถูกแก้หลังผมสั่งล่าสุดไหม (ดูเวลาแก้ไฟล์) และมีช่องตัวเลข ⟦...⟧ ที่ยังไม่ได้เติมไหม

### ขั้น 2: ถามผมให้ครบ

กติกาการถาม:
- ใช้เครื่องมือถามคำถาม (AskUserQuestion) ชุดละไม่เกิน 4 ข้อ ตัวเลือก 2 ถึง 4 ข้อ ใส่ตัวเลือกแนะนำเป็นข้อแรกและลงท้ายว่า "(แนะนำ)" ทุกตัวเลือกมีคำอธิบายสั้นว่ามีผลอย่างไร (ถ้าเกี่ยวกับเวลา โควตา หรือความเสี่ยงให้บอก)
- ข้อที่ต้องการข้อความอิสระ (เช่นที่อยู่อีเมล วันที่ รายวิชา) ให้ใช้ตัวเลือก "อื่น ๆ" ที่เครื่องมือมีให้
- **ข้ามข้อที่ตอบได้จากไฟล์แล้ว** (เช่น `ANSWERS.md`, ผลตรวจขั้น 1) แต่ให้บอกผมในบรรทัดเดียวว่าข้ามเพราะอะไร
- ห้ามถามเรื่องที่ตอบในไฟล์ prompt หลักไว้ชัดแล้ว (เช่น ใช้ NVENC ไหม, ตัวเลขต้องมาจากการวัดจริง)
- ลำดับการถาม: กลุ่ม A ก่อนเสมอ เพราะกำหนดว่าต้องถามกลุ่มไหนต่อ ที่เหลือถามต่อเนื่องจนครบ แล้วอย่าถามซ้ำอีก

| G1 | ไฟล์ส่งมอบมีข้อจำกัดขนาดหรือช่องทางส่งไหม (ระบุใน "อื่น ๆ" ถ้ามี เช่น ไม่เกินกี่ MB หรืออัปโหลดขึ้นระบบอะไร) | ไม่มีข้อจำกัด ใช้ H.264 + AAC มาตรฐาน (แนะนำ) / มีข้อจำกัดขนาด (ระบุ) |
| G2 | กำหนดส่งหรือวันนำเสนอ (ระบุใน "อื่น ๆ") ใช้ตัดสินว่าจะลดงานตรงไหนถ้าเวลาไม่พอ | ยังไม่มีกำหนดตายตัว (แนะนำ) / มี (ระบุวัน) |
| G3 | ส่วนถาม-ตอบ (หัวข้อ 12) | คงเป็นเอกสารเตรียมตอบสดอย่างเดียว (แนะนำ) / ทำเป็นการ์ดภาพนิ่งชุดหนึ่งไว้เปิดประกอบตอนตอบ / ทำเป็นคลิปสั้นแยก |
| G4 | สิ่งที่ห้ามให้เห็นในวิดีโอนอกเหนือจากที่ prompt หลักระบุ (ระบุใน "อื่น ๆ" ถ้ามี) | ไม่มีเพิ่ม (แนะนำ) / มี (ระบุ) |

หลังถามครบ ถ้ามีคำตอบที่ขัดกันหรือไม่แน่ใจ (เช่นเลือกไม่โชว์อีเมลจริงแต่ในสคริปต์ 8.1 ผมพูดว่าเปิดอีเมลจริงให้ดู) ให้ถามต่อเพิ่ม 1 ชุดเพื่อแก้ความขัดแย้ง และถ้าคำตอบทำให้ต้องแก้สคริปต์ (เช่นตัดข้อความเรื่องอีเมลจริง) ให้บอกผมว่าต้องแก้ประโยคไหน ห้ามแก้สคริปต์เอง

### ขั้น 3: บันทึกคำตอบ

เขียน `video/ANSWERS.md` เป็นตาราง รหัสคำถาม คำตอบ วันที่ตอบ (ไฟล์นี้อยู่ใน `.gitignore`) และสร้างหรืออัปเดต `video/STATE.md` ให้มีเซสชันที่จะทำและลิงก์ไปยัง `ANSWERS.md` ห้ามใส่คีย์หรือรหัสผ่านในไฟล์ใด ๆ

### ขั้น 4: สรุปแผนและขออนุมัติ

สรุปไม่เกิน 12 บรรทัด: เซสชันที่จะทำ ลำดับงานตามข้อ 8 ของ prompt หลัก ค่าที่ผมตอบสำคัญ ๆ (อีเมล มือถือ ดนตรี งบเครดิต ความละเอียด) สิ่งที่ยังขาดหรือเสี่ยง (เช่น ไฟล์เสียงยังไม่ครบ ตัวเลขทดสอบอาจเก่า APK เก่า) และงานที่ผมต้องทำเอง (เช่น เปิดโหมดห้ามรบกวนบนมือถือและ Windows, เสียบสาย, เปิดเว็บเมลในหน้าต่างของผม, ฟังหน้าเลือกเสียง) ถามผมคำถามเดียวว่า "เริ่มได้ไหม" แล้วหยุดรอคำตอบ ห้ามเริ่มก่อน

### หลังผมตอบ "เริ่ม"

ทำงานตาม `docs/video/PROMPT-motion-clip.md` เริ่มจากเซสชันที่ตกลงกัน หยุดที่จุดตรวจที่กำหนด และอัปเดต `video/STATE.md` ทุกขั้น ถ้าเจอเรื่องที่ต้องตัดสินใจและไม่มีคำตอบใน `ANSWERS.md` ให้ถามผมสั้น ๆ ทีละเรื่อง ห้ามเดา
